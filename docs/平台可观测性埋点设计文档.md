# K8sOperation 平台可观测性埋点设计文档

## 1. 概述

本文档说明 K8sOperation 平台的 **Prometheus 可观测性埋点方案**，覆盖 HTTP 请求、K8s 集群操作、CICD 流水线、认证授权、CRD 动态资源、数据库、系统运行时等 **8 大维度**，为平台稳定性监控和性能调优提供数据基础。

### 1.1 技术选型

| 组件 | 版本 | 说明 |
|------|------|------|
| Prometheus Client | `github.com/prometheus/client_golang` | Go 官方客户端库 |
| 指标暴露 | `promhttp.Handler()` | 标准 `/metrics` 端点 |
| 注册方式 | `promauto` | 自动注册到默认 Registry |
| 采集方式 | Gin 中间件 + 业务代码手动调用 | 两层埋点 |

### 1.2 架构图


## 2. 指标清单

### 2.1 HTTP 请求指标（自动采集）

这些指标由 `PrometheusMiddleware` 中间件**自动采集**，无需业务代码侵入。

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_http_requests_total` | Counter | method, path, status | HTTP 请求总量 |
| `k8sop_http_request_duration_seconds` | Histogram | method, path | 请求延迟分布（P50/P90/P99） |
| `k8sop_http_request_size_bytes` | Histogram | method, path | 请求体大小分布 |
| `k8sop_http_response_size_bytes` | Histogram | method, path | 响应体大小分布 |
| `k8sop_http_inflight_requests` | Gauge | - | 当前正在处理的并发请求数 |

**延迟 Bucket 分布**：5ms, 10ms, 25ms, 50ms, 100ms, 250ms, 500ms, 1s, 2.5s, 5s, 10s

**路径归一化规则**：
- 优先使用 Gin 注册的模板路径（如 `/api/v1/k8s/pod/list`）
- 动态路径段（UUID、数字 ID）自动替换为 `:uuid` / `:id`
- 路径深度限制为 7 级，防止基数爆炸

### 2.2 K8s 集群操作指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_k8s_api_calls_total` | Counter | cluster_id, resource, action, status | K8s API 调用总量 |
| `k8sop_k8s_api_call_duration_seconds` | Histogram | cluster_id, resource, action | K8s API 调用延迟 |
| `k8sop_k8s_cluster_status` | Gauge | cluster_id, cluster_name | 集群连接状态 (1=正常, 0=异常) |

**使用方式**（在 Controller/Service 层调用）：

```go
import "k8soperation/middlewares"

start := time.Now()
result, err := svc.ListDeployments(ctx, cli, namespace)
middlewares.RecordK8sAPICall(clusterID, "deployment", "list", err, time.Since(start))
```

### 2.3 CICD 流水线指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_cicd_pipeline_runs_total` | Counter | pipeline_name, status | 流水线运行总量 |
| `k8sop_cicd_pipeline_duration_seconds` | Histogram | pipeline_name | 流水线执行耗时 |
| `k8sop_cicd_build_queue_size` | Gauge | - | 当前构建队列大小 |

**耗时 Bucket**：10s, 30s, 1m, 2m, 5m, 10m, 20m, 30m, 60m

### 2.4 CRD/CR 动态资源指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_crd_operations_total` | Counter | resource_type, action, status | CRD/CR 操作总量 |

**使用方式**：

```go
middlewares.RecordCRDOperation("cr", "create", err)
middlewares.RecordCRDOperation("crd", "list", nil)
```

### 2.5 认证与权限指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_auth_login_total` | Counter | status | 用户登录总量（success/failed） |
| `k8sop_auth_token_validation_total` | Counter | status | JWT Token 校验总量（success/expired/invalid） |
| `k8sop_rbac_denied_total` | Counter | user, resource, action | 权限拒绝次数 |

> 已自动集成到 `AuthJWT()` 和 `ClusterMiddleware()` 中间件。

### 2.6 数据库指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_db_query_total` | Counter | table, operation | 数据库操作总量 |
| `k8sop_db_query_duration_seconds` | Histogram | table, operation | 数据库操作延迟 |
| `k8sop_db_connection_pool_active` | Gauge | - | 连接池活跃连接数 |

### 2.7 运行时指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `k8sop_runtime_panics_total` | Counter | - | panic 恢复总次数 |
| `k8sop_runtime_errors_total` | Counter | module, error_type | 业务错误总量 |
| `k8sop_ws_connections` | Gauge | - | 当前 WebSocket 连接数 |
| `k8sop_app_info` | Gauge | version, go_version, build_time | 应用版本信息（常量 = 1） |

### 2.8 Go 运行时标准指标（自动暴露）

Prometheus Go 客户端会自动暴露以下指标，**无需额外代码**：

| 指标名 | 说明 |
|--------|------|
| `go_goroutines` | 当前 Goroutine 数量 |
| `go_memstats_alloc_bytes` | 当前内存分配 |
| `go_memstats_heap_alloc_bytes` | 堆内存分配 |
| `go_gc_duration_seconds` | GC 耗时分布 |
| `go_threads` | OS 线程数 |
| `process_cpu_seconds_total` | CPU 使用时间 |
| `process_resident_memory_bytes` | 常驻内存 |
| `process_open_fds` | 打开的文件描述符数 |

## 3. 端点和配置

### 3.1 指标暴露端点

```
GET http://<host>:8080/metrics
```

- **无需认证**：`/metrics` 端点不走 JWT 中间件，允许 Prometheus 直接抓取
- **内容格式**：标准 Prometheus text exposition format

### 3.2 健康检查端点（已有）

```
GET /healthz/live    # 存活探针 (进程存活即返回 200)
GET /healthz/ready   # 就绪探针 (DB 可用才返回 200)
```

### 3.3 Prometheus 抓取配置

在 Prometheus 的 `prometheus.yml` 中添加：

```yaml
scrape_configs:
  - job_name: 'k8s-operation'
    scrape_interval: 15s
    static_configs:
      - targets: ['<backend-host>:8080']
    metrics_path: /metrics
```

如果部署在 K8s 集群中，可以使用 ServiceMonitor：

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: k8s-operation
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: k8s-operation
  endpoints:
    - port: http
      path: /metrics
      interval: 15s
  namespaceSelector:
    matchNames:
      - k8s-operation
```

## 4. 代码结构

```
k8s_operation/
├── pkg/metrics/
│   └── metrics.go                 # 所有 Prometheus 指标定义（8 大类）
├── middlewares/
│   ├── prometheus.go              # HTTP 指标采集中间件 + 业务埋点辅助函数
│   ├── auth.go                    # Token 校验埋点（已集成）
│   ├── cluster.go                 # RBAC 拒绝埋点（已集成）
│   └── recovery.go                # Panic 计数埋点（已集成）
└── initialize/
    └── server.go                  # 注册 PrometheusMiddleware + /metrics 端点
```

### 4.1 中间件注册顺序

```go
s.Use(middlewares.PrometheusMiddleware()) // ① 指标采集（最先）
s.Use(middlewares.Logger())               // ② 日志记录
s.Use(middlewares.Recovery())             // ③ Panic 恢复
s.Use(middlewares.K8sError())             // ④ K8s 错误处理
s.Use(middlewares.Audit(nil))             // ⑤ 审计日志
```

> PrometheusMiddleware 放在最前面，确保能采集到所有请求（包括被后续中间件拦截的）。

## 5. 关键告警规则建议

以下是建议配置的 Prometheus AlertManager 告警规则：

### 5.1 可用性告警

```yaml
groups:
  - name: k8sop-availability
    rules:
      # API 请求错误率 > 5%
      - alert: HighErrorRate
        expr: |
          sum(rate(k8sop_http_requests_total{status=~"5.."}[5m]))
          /
          sum(rate(k8sop_http_requests_total[5m])) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "K8sOperation API 错误率过高"
          description: "5xx 错误率 {{ $value | humanizePercentage }}"

      # 服务 panic 告警
      - alert: PanicOccurred
        expr: increase(k8sop_runtime_panics_total[5m]) > 0
        for: 0m
        labels:
          severity: critical
        annotations:
          summary: "K8sOperation 发生 Panic"
          description: "过去 5 分钟内发生 {{ $value }} 次 panic"
```

### 5.2 性能告警

```yaml
      # API P99 延迟 > 5s
      - alert: HighLatency
        expr: |
          histogram_quantile(0.99,
            sum(rate(k8sop_http_request_duration_seconds_bucket[5m])) by (le)
          ) > 5
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "API P99 延迟过高"
          description: "P99 延迟 {{ $value }}s"

      # 并发请求过高
      - alert: HighConcurrency
        expr: k8sop_http_inflight_requests > 100
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "并发请求数过高"
```

### 5.3 认证安全告警

```yaml
      # 连续认证失败
      - alert: HighAuthFailures
        expr: |
          sum(rate(k8sop_auth_token_validation_total{status!="success"}[5m])) > 10
        for: 3m
        labels:
          severity: warning
        annotations:
          summary: "Token 校验失败率过高（可能存在暴力破解）"

      # RBAC 权限拒绝频繁
      - alert: FrequentRBACDenied
        expr: sum(rate(k8sop_rbac_denied_total[5m])) > 5
        for: 5m
        labels:
          severity: info
        annotations:
          summary: "RBAC 权限拒绝频繁"
```

### 5.4 K8s 集群告警

```yaml
      # K8s API 调用失败率
      - alert: K8sAPIErrors
        expr: |
          sum(rate(k8sop_k8s_api_calls_total{status="error"}[5m]))
          /
          sum(rate(k8sop_k8s_api_calls_total[5m])) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "K8s API 调用失败率 > 10%"

      # 集群连接断开
      - alert: ClusterDown
        expr: k8sop_k8s_cluster_status == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "K8s 集群连接断开"
```

## 7. 业务层埋点指南

### 7.1 在 Controller 中埋点

```go
import "k8soperation/middlewares"

func (c *Controller) CreateDeployment(ctx *gin.Context) {
    start := time.Now()
    // ... 业务逻辑 ...
    err := svc.CreateDeployment(ctx, cli, req)
    // 埋点
    middlewares.RecordK8sAPICall(clusterID, "deployment", "create", err, time.Since(start))
}
```

### 7.2 CRD 操作埋点

```go
func (c *DynamicCRDController) ListCRDs(ctx *gin.Context) {
    items, total, err := svc.KubeCRDList(ctx, cli, keyword, group)
    middlewares.RecordCRDOperation("crd", "list", err)
}

func (c *DynamicCRDController) CreateCR(ctx *gin.Context) {
    obj, err := svc.KubeCRCreate(ctx, cli, ...)
    middlewares.RecordCRDOperation("cr", "create", err)
}
```

### 7.3 登录埋点

```go
func (c *AuthController) Login(ctx *gin.Context) {
    user, err := svc.Login(username, password)
    middlewares.RecordAuthLogin(err == nil)
}
```

### 7.4 流水线埋点

```go
func onPipelineComplete(pipelineName string, status string, startTime time.Time) {
    middlewares.RecordPipelineRun(pipelineName, status, time.Since(startTime))
}
```

## 10. 指标命名规范

所有指标遵循 Prometheus 命名规范：

```
k8sop_{subsystem}_{metric_name}_{unit}
```

| 前缀 | 子系统 | 示例 |
|------|--------|------|
| `k8sop_http_` | HTTP 层 | `k8sop_http_requests_total` |
| `k8sop_k8s_` | K8s 操作 | `k8sop_k8s_api_calls_total` |
| `k8sop_cicd_` | CICD | `k8sop_cicd_pipeline_runs_total` |
| `k8sop_crd_` | CRD 扩展 | `k8sop_crd_operations_total` |
| `k8sop_auth_` | 认证 | `k8sop_auth_login_total` |
| `k8sop_rbac_` | 权限 | `k8sop_rbac_denied_total` |
| `k8sop_db_` | 数据库 | `k8sop_db_query_total` |
| `k8sop_runtime_` | 运行时 | `k8sop_runtime_panics_total` |
| `k8sop_ws_` | WebSocket | `k8sop_ws_connections` |
| `k8sop_app_` | 应用信息 | `k8sop_app_info` |
