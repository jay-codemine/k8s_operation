# 开发者快速发布操作手册

> 面向开发人员，快速掌握从代码提交到线上发布的完整操作流程。

---

## 一、发布方式总览

| 方式 | 适用场景 | 耗时 | 操作入口 |
|------|----------|------|---------|
| **标准发布** | 日常开发、功能迭代 | 3-10 分钟 | CI/CD → 流水线 → 发布 |
| **极速发布** | 紧急修复、指定镜像直接部署 | 几秒 | CI/CD → 发布单 → 创建 |
| **一键回滚** | 线上故障、版本回退 | 几秒 | 流水线详情 → 回滚 |

---

## 二、标准发布操作（日常开发）

### 操作步骤（4 步完成发布）

#### 第 1 步：提交代码到 Git

```bash
git add .
git commit -m "feat: 新增用户导出功能"
git push origin master
```

#### 第 2 步：登录平台，发布流水线

1. 打开平台 → **CI/CD → 流水线管理**
2. 找到对应项目的流水线
3. 点击右侧 **「▶ 发布」** 按钮
4. 确认分支（默认为流水线配置的分支），点击确认

> 💡 如果流水线正在运行，按钮显示为 **「重新发布」**。

#### 第 3 步：等待发布完成

- 进入流水线详情页，实时查看执行阶段进度
- 阶段状态说明：⏳ 等待 → 🔄 执行中 → ✅ 成功 / ❌ 失败
- 典型耗时参考：

| 语言类型 | 构建耗时 | 部署耗时 |
|---------|---------|---------|
| Go | ~2-3 分钟 | ~10 秒 |
| Java (Maven) | ~4-6 分钟 | ~15 秒 |
| 前端 (Vue/React) | ~2-3 分钟 | ~10 秒 |
| Python | ~1-2 分钟 | ~10 秒 |

#### 第 4 步：确认飞书通知

发布过程中会收到 **两条飞书通知**：

```
📱 通知 1：【开发环境发布开始】
  ├── 📦 应用：springboot-hello
  ├── 🌿 分支：master
  ├── 🔢 构建号：#18
  ├── 👤 发布人：admin
  ├── 🕐 开始时间：2026-06-22 10:19:24
  └── 🟡 状态：开发环境发布中，请等待...

📱 通知 2：【开发环境发布完成】
  ├── 📦 应用：springboot-hello
  ├── 🌿 分支：master
  ├── 🐳 镜像版本：registry.cn-hangzhou.../springboot-hello:3d132b7-20260622
  ├── ⏱️ 发布耗时：12s
  ├── ✅ 发布结果：Deployment Ready / Pod Ready: 1/1
  └── 🟢 状态：开发环境发布完成
```

## 三、极速发布（紧急修复 / 指定镜像）

> 跳过 Jenkins 构建，直接将已有镜像部署到 K8s，秒级完成。

### 适用场景

- 紧急 hotfix 已在本地构建好镜像并推送到仓库
- 需要将特定版本镜像部署到指定环境
- 镜像已通过 CI 验证，同步到其他集群

### 操作步骤

1. 进入 **CI/CD → 发布单** 页面
2. 点击 **「创建发布单」**
3. 填写信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 应用名称 | 应用标识 | `user-service` |
| 命名空间 | K8s Namespace | `default` |
| 工作负载名称 | Deployment 名称 | `user-service` |
| 容器名称 | Pod 中的容器名 | `app` |
| 镜像仓库 | Registry 地址 | `registry.cn-hangzhou.aliyuncs.com/k8s-gos/user-service` |
| 镜像 Tag | 部署版本 | `hotfix-20260622` |
| 目标集群 | 部署到哪个集群 | `default-cluster` |

4. 点击 **提交** → 几秒内完成部署

## 四、一键回滚

### 操作方式

1. 进入流水线详情 → **运行历史** tab
2. 找到上一个成功版本
3. 点击 **「回滚」** 按钮
4. 系统自动使用旧版本镜像执行部署，秒级恢复

---

## 五、新项目首次接入

### 前置条件

- 代码已托管到 Git 仓库（Gitee / GitLab / GitHub）
- 平台已接入目标 K8s 集群
- Jenkins 已就绪

### 创建流水线（3 分钟完成）

1. 进入 **CI/CD → 流水线管理 → 创建流水线**
2. 填写基本信息：

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 流水线名称 | 如 `user-service-dev` | ✅ |
| 语言类型 | go / java / frontend / python | ✅ |
| Git 仓库地址 | 完整仓库 URL | ✅ |
| 默认分支 | master / main / develop | ✅ |
| 镜像仓库地址 | 如 `registry.cn-hangzhou.../my-app` | ✅ |

3. 配置自动部署（推荐开发/测试环境开启）：

| 配置项 | 说明 |
|--------|------|
| 启用自动部署 | ✅ 开启 |
| 目标集群 | 选择部署集群 |
| 命名空间 | 如 `default` |
| 工作负载名称 | 如 `user-service` |
| 容器名称 | 如 `app` |

4. 保存 → 点击 **「发布」** 按钮验证首次发布

### 支持的语言模板

| 语言类型 | Jenkins Job | 构建工具 |
|---------|-------------|---------|
| **Go** | `go-pipeline` | go build |
| **Java** | `java-spring-pipeline` | Maven |
| **前端** | `frontend-pipeline` | npm / pnpm |
| **Python** | `python-pipeline` | pip |

## 六、多环境发布策略

| 环境 | 推荐分支 | 自动部署 | 审批 | 说明 |
|------|---------|---------|------|------|
| 开发 (DEV) | `dev` / `feature/*` | ✅ | 无 | 开发自测 |
| 测试 (TEST) | `develop` | ✅ | 无 | QA 验证 |
| 预发 (STAGING) | `release` | ✅ | 无 | 上线前验收 |
| 生产 (PROD) | `main` / `master` | ❌ 审批后部署 | **需要审批** | 正式上线 |

## 七、常用操作速查

| 操作 | 路径 |
|------|------|
| 发布流水线 | 流水线列表 → **「▶ 发布」** |
| 查看阶段进度 | 流水线详情 → **执行阶段** tab |

| 重新发布 | 流水线详情 → **「重新发布」** |
| 回滚到历史版本 | 运行历史 → 选择版本 → **「回滚」** |
| 极速发布 | 发布单 → **「创建发布单」** |
| 编辑流水线配置 | 流水线详情 → **「编辑」** |

## 八、发布状态说明

| 状态 | 含义 | 开发者操作 |
|------|------|-----------|
| ⏳ PENDING | 排队等待 | 等待 |
| 🔄 RUNNING | 构建/部署中 | 等待，可查看实时日志 |
| ✅ SUCCESS | 发布成功 | 验证线上功能 |
| ❌ FAILED | 发布失败 | 查看日志修复问题 |
| ⏹ ABORTED | 已取消 | 可重新发布 |
| ⏳ PENDING_APPROVAL | 等待审批（生产环境） | 通知审批人 |

## 九、常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 点击发布后一直 PENDING | Jenkins 队列满 | 等待或联系运维 |
| 构建失败：代码检出错误 | Git 凭证过期 | 联系运维更新 Jenkins 凭证 |
| 构建失败：编译报错 | 代码语法错误 | 查看构建日志，修复代码后重新发布 |
| 构建失败：镜像推送失败 | 镜像仓库认证失败 | 联系运维检查 Registry 凭证 |
| 发布成功但没有通知 | 飞书 Webhook 未配置 | 联系运维检查 `config.yaml` 中飞书配置 |
| 部署失败：ImagePullBackOff | 镜像拉取失败 | 检查镜像地址是否正确，K8s 是否有镜像仓库凭证 |
| 部署失败：CrashLoopBackOff | 应用启动崩溃 | 查看 Pod 日志，修复应用启动问题 |
| 部署超时 | 健康检查未通过 | 检查应用健康检查接口是否正常 |
| 构建成功但没自动部署 | 未开启自动部署 | 编辑流水线 → 开启「自动部署」 |

## 十、API 快速参考

```bash
# 发布流水线
POST /api/v1/k8s/cicd/pipeline/run
Body: { "id": 流水线ID, "branch": "master" }

# 查看发布状态
GET /api/v1/k8s/cicd/pipeline/status?id=流水线ID

# 查看构建日志
GET /api/v1/k8s/cicd/pipeline/logs?id=流水线ID

# 极速发布（指定镜像）
POST /api/v1/k8s/cicd/release/create
Body: { "pipeline_id": 5, "image_tag": "v1.2.0" }

# 停止发布
POST /api/v1/k8s/cicd/pipeline/stop
Body: { "id": 流水线ID }

# 回滚
POST /api/v1/k8s/cicd/release/rollback
Body: { "id": 发布单ID }
```
