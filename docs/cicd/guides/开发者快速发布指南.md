# 开发者快速发布指南

> 面向开发人员，快速掌握从代码到线上的完整发布流程。

---

## 一、发布方式总览

| 方式 | 适用场景 | 耗时 | 是否需要 Jenkins |
|------|----------|------|-----------------|
| **完整发布** | 日常开发、代码变更 | 3-10 分钟 | 需要 |
| **极速发布** | 紧急热修、回滚、镜像已有 | 几秒 | 不需要 |

---

## 二、完整发布流程（日常开发）

### 全链路流程图

```
                    开发者推送代码到 Git
                          │
                          ▼
          ┌───────────────────────────────┐
          │   平台「运行流水线」按钮触发     │
          └───────────────┬───────────────┘
                          ▼
     ┌────────────────────────────────────────┐
     │        Jenkins 自动执行（14阶段）        │
     │                                        │
     │  ① Clean + Checkout（清理+拉取代码）     │
     │  ② Dependencies（下载依赖）              │
     │  ③ Compile（编译检查）                   │
     │  ④ Test（单元测试）                      │
     │  ⑤ Lint（代码检查）                      │
     │  ⑥ SonarQube（质量扫描）[可选]           │
     │  ⑦ Quality Gate（质量门禁）[可选]        │
     │  ⑧ Build Binary（编译产物）              │
     │  ⑨ Upload Artifact（制品上传）[可选]     │
     │  ⑩ Build Image（nerdctl build）         │
     │  ⑪ Push Image（推送到镜像仓库）          │
     │  ⑫ Callback（回调平台）                  │
     └────────────────────┬───────────────────┘
                          ▼
          ┌───────────────────────────────┐
          │   平台收到回调，进入部署流程     │
          │                               │
          │  • 无审批 → 自动部署            │
          │  • 需审批 → 等待审批通过后部署   │
          └───────────────┬───────────────┘
                          ▼
          ┌───────────────────────────────┐
          │   滚动更新 K8s Deployment      │
          │   → 等待 Rollout 完成          │
          │   → 发送通知（钉钉/飞书）       │
          └───────────────────────────────┘
```

### 操作步骤（5步完成）

#### 第 1 步：提交代码

```bash
git add .
git commit -m "feat: 新增用户导出功能"
git push origin main
```

#### 第 2 步：登录平台，找到流水线

1. 打开平台 → **CI/CD → 流水线**
2. 找到对应项目的流水线（如 `user-service-dev`）

#### 第 3 步：运行流水线

1. 点击流水线右侧的 **「运行」** 按钮
2. 确认/修改构建分支（默认使用流水线配置的分支）
3. 点击确认

#### 第 4 步：等待构建完成

- 进入流水线详情页，实时查看 14 阶段执行进度
- 每个阶段状态：⏳ 排队 → 🔄 执行中 → ✅ 成功 / ❌ 失败
- 典型耗时：Go 项目 ~3 分钟，Java 项目 ~5 分钟，前端 ~3 分钟

#### 第 5 步：验证部署

- 构建完成后如配置了「自动部署」→ 自动更新 K8s 工作负载
- 检查平台上的部署状态为 ✅ SUCCEEDED
- 访问应用验证功能正常

## 三、极速发布流程（紧急修复/回滚）

> 跳过 Jenkins 构建，直接将已有镜像部署到 K8s，秒级完成。

### 适用场景

- 紧急 hotfix 已在本地构建好镜像
- 需要回滚到上一个版本
- 镜像已通过 CI 验证，只需同步到其他集群

### 操作步骤

#### 方式一：界面操作

1. 进入 **CI/CD → 发布单** 页面
2. 点击 **「创建发布单」**
3. 填写信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 应用名称 | 应用标识 | `user-service` |
| 命名空间 | K8s Namespace | `production` |
| 工作负载类型 | Deployment/StatefulSet | `Deployment` |
| 工作负载名称 | 要更新的工作负载 | `user-service` |
| 容器名称 | 要更新镜像的容器 | `app` |
| 镜像仓库 | Registry 地址 | `harbor.example.com/proj/user-service` |
| 镜像 Tag | 要部署的版本 | `hotfix-001` |
| 目标集群 | 选择集群（支持多选） | cluster-prod |

4. 点击 **提交** → 系统几秒内完成部署

#### 方式二：基于流水线快捷发布

如果已有流水线，只需传入 `pipeline_id + image_tag`：

```bash
curl -X POST http://平台地址/api/v1/k8s/cicd/release/create \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "pipeline_id": 5,
    "image_tag": "v1.2.0"
  }'
```

> 系统自动从流水线配置中继承所有部署参数，无需重复填写。

#### 方式三：一键回滚

1. 进入 **发布单列表** / **流水线详情 → 部署历史**
2. 找到上一个成功版本
3. 点击 **「回滚」** 按钮
4. 系统自动使用旧镜像创建发布单并执行

## 四、新项目首次接入 CI/CD

### 前置条件

- 项目代码已在 Git 仓库（Gitee/GitLab/GitHub）
- 平台已接入目标 K8s 集群
- Jenkins 已初始化（4 个 Builder Job 已创建）

### 接入步骤

```
1. 确认项目语言类型（go / java / frontend / python）
2. 在平台「创建流水线」→ 选择语言类型
   ✅ Jenkins Job 自动映射，无需手动配置
3. 填写 Git 仓库地址和默认分支
4. 填写镜像仓库地址（如 harbor.example.com/proj/my-app）
5. 配置部署目标：
   - 目标集群
   - 命名空间
   - 工作负载名称（Deployment/StatefulSet）
   - 容器名称
6. 保存 → 首次手动「运行」验证
7. 验证通过后即可日常使用
```

### 支持的语言模板

| 语言类型 | Jenkins Job | 构建流程 |
|---------|-------------|----------|
| **Go** | `k8s-builder-go` | go test → lint → build → nerdctl build/push |
| **Java** | `k8s-builder-java` | mvn compile → test → SonarQube → package → nerdctl build/push |
| **前端** | `k8s-builder-frontend` | npm ci → lint → build → nerdctl build(Nginx)/push |
| **Python** | `k8s-builder-python` | pip install → flake8 → pytest → nerdctl build/push |

## 五、多环境发布策略

### 环境配置对照

| 环境 | 分支 | 自动部署 | SonarQube | 审批 |
|------|------|---------|-----------|------|
| DEV | `dev` / `feature/*` | ✅ 自动 | ❌ 关闭 | 不需要 |
| TEST | `test` / `develop` | ✅ 自动 | ✅ 开启 | 不需要 |
| STAGING | `release` | ✅ 自动 | ✅ 开启 + 质量门禁 | 不需要 |
| PROD | `main` / `master` | ❌ 手动审批后部署 | ✅ 开启 + 质量门禁 | **需要审批** |

### 推荐工作流

```
开发环境：
  feature/* 分支 → 创建 MR 到 develop → CI 自动构建部署到 DEV

测试环境：
  develop 分支 → CI 自动构建部署到 TEST → 测试验证

预发环境：
  develop → release 分支 MR → CI 部署到 STAGING → 验收

生产环境：
  release → main 分支 MR → 触发构建 → 审批通过 → 部署到 PROD
```

## 六、发布状态说明

| 状态 | 含义 | 下一步操作 |
|------|------|-----------|
| PENDING | 等待执行 | 自动进入队列 |
| BUILDING | Jenkins 构建中 | 等待 |
| BUILD_SUCCESS | 构建成功，等待部署 | 等待自动部署/手动审批 |
| BUILD_FAILED | 构建失败 | 查看日志修复问题 |
| PENDING_APPROVAL | 等待审批 | 通知审批人 |
| APPROVED | 审批通过 | 自动进入部署 |
| DEPLOYING | 正在部署（Rollout 中） | 等待 |
| SUCCEEDED | 发布成功 ✅ | 完成 |
| FAILED | 发布失败 | 查看原因，回滚或重试 |
| ROLLED_BACK | 已回滚 | 修复后重新发布 |
| CANCELLED | 已取消 | - |

## 七、常见操作速查

### 7.1 查看构建日志

流水线详情 → 点击对应阶段 → 查看日志输出

### 7.2 停止正在运行的构建

流水线详情 → 点击 **「停止」** 按钮

### 7.3 重新运行失败的构建

流水线详情 → 点击 **「重新运行」**

### 7.4 紧急回滚

```
方式 1：流水线详情 → 部署历史 → 选择历史版本 → 「回滚」
方式 2：发布单列表 → 找到发布记录 → 「回滚」
方式 3：极速发布 → 填入上一版本的镜像 Tag
```

### 7.5 批量发布到多集群

发布单 → 创建时选择多个目标集群 → 设置并发数 → 提交

## 八、常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 构建失败：代码检出失败 | Git 凭证无效 | 联系运维检查 Jenkins Git 凭证 |
| 构建失败：编译错误 | 代码有语法错误 | 查看构建日志，修复代码 |
| 构建失败：镜像推送失败 | Registry 认证失败 | 联系运维检查 Harbor 凭证 |
| 流水线一直「运行中」 | Jenkins 卡住 | 使用「停止」按钮，或联系运维 |
| 部署失败 | 镜像拉取失败/资源不足 | 查看 K8s Pod 事件日志 |
| 构建成功但没自动部署 | 未开启自动部署 | 编辑流水线开启「自动部署」开关 |

## 九、API 快速参考（高频接口）

```bash
# 运行流水线
POST /api/v1/k8s/cicd/pipeline/run
Body: { "id": 流水线ID, "branch": "main" }

# 查看运行状态
GET /api/v1/k8s/cicd/pipeline/status?id=流水线ID

# 查看构建日志
GET /api/v1/k8s/cicd/pipeline/logs?id=流水线ID

# 极速发布（基于流水线）
POST /api/v1/k8s/cicd/release/create
Body: { "pipeline_id": 5, "image_tag": "v1.2.0" }

# 回滚
POST /api/v1/k8s/cicd/release/rollback
Body: { "id": 发布单ID }

# 停止构建
POST /api/v1/k8s/cicd/pipeline/stop
Body: { "id": 流水线ID }
```
