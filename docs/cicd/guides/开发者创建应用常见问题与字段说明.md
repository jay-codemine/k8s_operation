# 开发者创建应用 — 常见问题与字段说明

> 面向开发人员，解答「新建应用/流水线」页面中各字段的用途、填错会怎样、不填某项会有什么影响。

---

## 一、页面总览

平台提供两种创建方式：

| 方式 | 适用人群 | 必填字段数 |
|------|---------|-----------|
| **极简模式**（默认） | 普通开发者 | 最少 3 个（应用名 + Git仓库 + 语言类型） |
| **完整模式** | 需精细配置的高级用户 | 按需填写，分 4 个步骤 |

---

## 二、字段说明 & 填错会怎样

### 2.1 应用名称（必填）

**作用**：
- 唯一标识一个应用，对应后端数据库中的 `name` 字段
- **自动作为** K8s 工作负载名称（Deployment/StatefulSet 名称）和容器名称
- 例如填 `springboot-hello`，K8s 里会创建同名 Deployment

**规则**：
- 只能使用小写字母、数字、连字符（`-`）
- 不能重复（平台会检查，重复立即报错：「流水线名称已存在」）
- 建议与项目仓库名保持一致

**填错会怎样**：

| 情况 | 平台反应 |
|------|---------|
| 名称已存在 | 立即报错「流水线名称已存在」，不允许创建 |
| 包含大写/特殊字符 | 表单不允许提交（前端校验） |
| 留空 | 表单不允许提交 |

---

### 2.2 Git 仓库地址（必填）

**作用**：
- 告诉 Jenkins 从哪里拉取源代码
- 必须是完整的 HTTP/HTTPS/SSH 地址，例如：
  - `https://gitee.com/jay-kim/sprinboot-hello`
  - `https://github.com/org/project.git`

**填错会怎样**：

| 情况 | 平台反应 |
|------|---------|
| 格式不正确（非URL） | 表单不允许提交（前端 URL 格式校验） |
| 地址格式正确但仓库不存在 | **平台创建成功**，但触发构建时 Jenkins 报错：`Failed to clone repository`，构建状态变为 **「构建失败」** |
| 私有仓库未配置凭证 | 同上，Jenkins 报错：`Authentication failed` |
| 仓库地址拼写错误 | 同「仓库不存在」处理 |

> ⚠️ **重点**：平台在创建阶段**不会验证仓库是否真实可达**，只做 URL 格式检查。真正的验证发生在 Jenkins 触发构建时。如果地址填错，在「流水线管理」中点击编辑修改即可，不需要重新创建。

---

### 2.3 语言/框架类型（必填）

**作用**：
- 告诉平台使用哪套 Jenkins 构建模板
- 决定 Jenkins 自动选用的 Job 名称

| 语言类型 | 自动使用的 Jenkins Job | 构建工具 |
|---------|----------------------|---------|
| Java | `k8s-builder-java` | Maven |
| Go | `k8s-builder-go` | go build |
| Node.js | `k8s-builder-frontend` | npm run build |
| Python | `k8s-builder-python` | pip / gunicorn |
| 自定义 | 需手动填写 Jenkins Job 名 | 自定义 |

**填错会怎样**：

| 情况 | 平台反应 |
|------|---------|
| 选错语言（如 Java 项目选了 Go） | 创建成功，但构建时 Jenkins 用错模板，**编译失败** |
| 没有选择（默认 Go） | 按 Go 构建，Java 项目会报编译错误 |

> 填错了可以随时在「流水线管理 → 编辑」中修改，不影响已创建的记录。

---

### 2.4 镜像仓库地址（强烈推荐填写）

**作用**：
- 告诉 Jenkins 把构建好的 Docker 镜像推送到哪里
- 格式：`registry地址/项目名/应用名`，例如：
  - `harbor.company.com/backend/springboot-hello`
  - `registry.cn-hangzhou.aliyuncs.com/myproject/app`

**不填会怎样**：
- Jenkins 构建成功但**不会推送镜像**，后续无法通过平台部署到 K8s
- 可以后期在「流水线管理 → 编辑」补填

---

### 2.5 自动部署配置（可选）

**作用**：
- 勾选后，Jenkins 构建并推送镜像完成后，**自动更新 K8s 里的工作负载镜像**，实现 CI+CD 全自动

#### 不开自动部署，效果是什么？

```
Git Push
  ↓
Jenkins 拉代码 → 编译 → 打包镜像 → 推送到镜像仓库
  ↓
✅ 到这里就结束了（只有 CI，没有 CD）
  ↓
❌ 不会自动部署到 K8s
```

> 开发者需要手动去「**发布管理**」→「创建发布」，选择应用 + 填写版本号，才能触发 K8s 部署。

#### 开启自动部署，效果是什么？

```
Git Push
  ↓
Jenkins 拉代码 → 编译 → 打包镜像 → 推送镜像仓库
  ↓
平台自动触发部署 → 更新 K8s Deployment 镜像
  ↓
✅ 新版本自动上线（全自动 CI/CD）
```

#### 自动部署相关字段说明

| 字段 | 说明 | 不填的默认值 |
|------|------|------------|
| **目标集群** | 部署到哪个 K8s 集群 | 必须选择 |
| **命名空间** | 部署到集群的哪个 namespace | `default` |
| **工作负载名称** | K8s 里 Deployment 的名称 | **自动等于应用名称** |
| **容器名称** | Pod 里容器的名称 | **自动等于工作负载名称** |

> 💡 **极简模式下**：工作负载名称和容器名称**完全自动从应用名称派生**，开发者无需关心，这就是为什么极简模式里没有单独的「应用名」字段——它们都等于你填的「应用名称」。

## 三、集群列表为空的原因

截图中看到集群可以选择但「应用名」看起来消失了，这有两个原因：

### 原因 1：K8s 集群未初始化（最常见）

后端日志中出现：
```
K8s 集群未初始化（空启动模式）
→ 请通过 Web 界面添加集群
```

**解决方法**：
1. 进入「**集群管理**」菜单
2. 点击「添加集群」，上传有效的 kubeconfig 文件
3. 或将本地 kubeconfig 内容放入 `configs/k8s.yaml`，重启后端

### 原因 2：工作负载名称是自动填入的

平台设计上，极简模式中**不显示工作负载名称输入框**，因为它直接等于你的应用名称。后端代码逻辑：

```go
// 工作负载名称默认取流水线名称
if workloadName == "" && req.AutoDeploy {
    workloadName = strings.TrimSuffix(req.Name, "-pipeline")
    // 还会自动去掉 -prod、-dev、-test 等后缀
}
```

即：你填了「应用名称 = springboot-hello」，K8s 里自动创建名为 `springboot-hello` 的 Deployment。

## 四、开发者到底需要填哪些字段？

### 极简模式（推荐 99% 的日常使用）

```
✅ 必填：
  1. 应用名称        → springboot-hello
  2. Git 仓库地址    → https://gitee.com/jay-kim/sprinboot-hello
  3. 语言类型        → 选 Java

🟡 强烈推荐：
  4. 镜像仓库地址    → harbor.company.com/backend/springboot-hello

🔵 可选（需要自动部署时填）：
  5. 目标集群        → 选择可用的 K8s 集群
  6. 命名空间        → 留空默认 default
```

### 完整模式（需要精细控制时使用）

| 步骤 | 字段 | 开发者要做什么 |
|------|------|--------------|
| Step 1 应用信息 | 应用名 + 语言 + Git仓库 + 分支 | 必须填写 |
| Step 2 构建配置 | 镜像仓库 + Dockerfile策略 | 填镜像仓库，其余默认即可 |
| Step 3 部署策略 | 副本数 + 更新策略 | 保持默认（滚动更新 × 1副本）|
| Step 4 自动部署 | 集群 + namespace + 工作负载 | 需要自动部署才填 |

## 五、填错了怎么修改？

**不需要删除重建！** 所有字段都可以在「流水线管理 → 点击编辑」中修改：

- 修改 Git 仓库地址
- 修改语言类型
- 补填镜像仓库
- 修改自动部署目标

> 修改后，下次触发构建就会使用新配置。

## 六、常见错误快速排查表

| 现象 | 原因 | 解决方法 |
|------|------|---------|
| 创建时报「流水线名称已存在」 | 应用名重复 | 换一个名称 |
| 触发构建后状态一直「失败」 | Git 仓库地址错误或无访问权限 | 编辑流水线修改地址；配置 Jenkins 凭证 |
| 构建成功但 K8s 没有更新 | 没开自动部署 或 集群未配置 | 去「发布管理」手动发布；或编辑流水线开启自动部署 |
| 集群列表为空 | K8s 集群未在平台注册 | 「集群管理」中添加集群 |
| 镜像仓库为空导致发布失败 | 没填 IMAGE_REPO | 编辑流水线补填镜像仓库地址 |
| 应用名在集群选择区域不见了 | 正常！工作负载名自动等于应用名 | 无需操作 |
