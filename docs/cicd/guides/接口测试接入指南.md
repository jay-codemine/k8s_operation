# 接口测试（Postman/Newman）接入指南

## 一、能力说明

平台的四个 Jenkins 构建模板（Go / 前端 / Python / Java）均已内置**接口测试阶段**：

- 用 **Newman**（Postman 的命令行工具）跑 Postman 集合
- 测试人员在 Postman 中维护用例，无需写代码
- 接口测试失败 → 流水线构建失败 → 镜像不会继续晋级部署
- 测试结果生成 **JUnit 报告**，在 Jenkins 里可视化查看

> 接口测试阶段默认**关闭**（`ENABLE_API_TEST=false`），不影响现有构建流程。

## 二、前置准备：编写 Postman 集合

1. 测试人员用 **Postman** 编写接口用例（请求 + 断言）。
2. 集合内的域名/地址**不要硬编码**，统一用变量 `{{baseUrl}}`：

   ```
   GET {{baseUrl}}/api/v1/namespaces
   ```

3. 导出集合文件：`Collection → Export → collection.json`。
4. （可选）如需管理多套环境变量（dev/test/staging 各自的 token、header 等），导出环境文件 `environment.json`。

## 三、接入步骤

1. 把 `collection.json`（和可选的 `environment.json`）放进应用仓库，例如：

   ```
   test/
   └── postman/
       ├── collection.json
       └── environment.json
   ```

2. 提交并推送代码。
3. 在平台流水线配置中开启接口测试并填写参数（见下表）。

## 四、参数说明

| 参数 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `ENABLE_API_TEST` | 是 | 开启接口测试 | `true` |
| `API_TEST_COLLECTION` | 是 | 集合路径（仓库内相对路径）或 URL | `test/postman/collection.json` |
| `API_TEST_ENVIRONMENT` | 否 | 环境文件路径或 URL | `test/postman/environment.json` |
| `API_TEST_BASE_URL` | 否 | 被测服务 BaseURL，注入为 `{{baseUrl}}` | `http://test.example.com` |
| `API_TEST_TIMEOUT` | 否 | 单请求超时（毫秒） | `30000` |

说明：

- `API_TEST_COLLECTION` 支持 **URL**（如 Postman 团队库的导出链接），会自动下载后运行。
- `API_TEST_BASE_URL` 优先级**高于**环境文件里的 `baseUrl`，适合「同一集合 + 不同环境」切换。
- 建议为 test 环境配 `API_TEST_BASE_URL=http://<测试环境域名>`，这样集合无需改动即可指向不同环境。

## 五、测试报告查看

构建完成后，在 Jenkins 构建页：

- **Test Result**：接口测试的 JUnit 报告，可看到每个用例的通过/失败与断言详情。
- **Artifacts**：归档的 `api-test-results.xml`，可下载留档。

接口测试失败时，`API Test` 阶段标记为失败，流水线整体失败，测试人员可从 Jenkins 控制台日志定位具体失败的用例和断言。

## 六、多服务 / 多环境说明

接口测试用例常常依赖多个微服务同时运行（例如下单流程依赖用户、订单、支付、网关）。正确做法是：

1. **测试环境常驻**：所有微服务在 test 环境各自独立部署、常驻运行，各自有当前稳定版本。
2. **按需单发**：测试某个服务的新版本时，**只发布该服务**，其余服务不动，它们通过服务发现/域名互相调用。
3. **接口兼容即可联调**：只要新版本的接口契约向下兼容，其余服务无需重新发布。

只有当某个服务做了**破坏性变更**（接口字段、协议不兼容，导致老版本调不通）时，才需要把相关服务**一起发布**——此时需使用「应用组/多服务编排」能力（平台目前未内置，需要时另行评估）。

## 七、注意事项

- `newman` 容器镜像使用平台私有镜像代理：`swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/postman/newman:alpine`。若集群无法拉取，请同步该镜像到你的镜像仓库并修改模板中的镜像地址。
- 四个模板统一使用 `newman` 容器（`postman/newman:alpine` 镜像），无需在各语言容器里额外装 Node/Newman。
- 接口测试阶段位于「单元测试」之后、镜像构建之前，执行顺序为：检出 → 依赖 → 编译 → 单元测试 → **接口测试** → 代码扫描 → 构建镜像。
