# 开发者新建应用与快速发布指南

> 本文档面向开发者，说明如何通过平台前台页面**注册新应用**并**快速完成第一次发布**。

---

## 总体流程

```
第一步：新建应用（只需填 3 个字段）
    ↓
第二步：触发构建（git push 或手动触发）
    ↓
第三步：创建发布单（选应用 + 填版本号）
    ↓
第四步：平台自动部署到 K8s ✅
```

> **日常发布（第二次起）只需：选应用 → 填版本号 → 确认**，全程不超过 30 秒。

---

## 第一步：新建应用

### 入口

**导航栏 → CI/CD → 流水线 → 「新建应用」按钮**

或在「发布管理」页空状态时直接点击「**快速新建应用**」。

---

### 必填字段（极简模式，3 个字段）

| 字段 | 说明 | 示例 |
|------|------|------|
| **应用名称（流水线名称）** ⭐必填 | 用小写字母、数字和连字符命名，同时作为 K8s 工作负载名称 | `user-service`、`order-api`、`frontend-web` |
| **Git 仓库地址** ⭐必填 | 代码仓库的 HTTPS 或 SSH 地址 | `https://gitee.com/org/user-service.git` |
| **语言 / 框架类型** ⭐必填 | 点击选择，平台自动匹配构建模板 | `Java` / `Go` / `Node.js` / `Python` |

---

### 推荐填写（非必填，但建议填）

| 字段 | 说明 | 示例 |
|------|------|------|
| **镜像仓库地址**（推荐） | Jenkins 构建完成后镜像推送到哪里；发布时自动读取 | `harbor.example.com/project/user-service` |
| **构建成功后自动部署到 K8s**（可选） | 勾选后每次构建成功自动部署，无需手动创建发布单 | ✅ 勾选 + 选择目标集群 + 命名空间 |

> 如果勾选「自动部署」，还需选择：
> - **目标集群**（下拉选择已接入的 K8s 集群）
> - **命名空间**（留空默认 `default`）
>
> 工作负载名称、容器名称自动使用应用名，无需手填。

---

### 自动生成的内容（无需操心）

平台创建应用后会自动完成以下配置，开发者无需关心：

- ✅ Jenkins Job 创建
- ✅ 构建模板绑定（根据语言类型自动选择）
- ✅ Git 凭证注入
- ✅ 镜像推送凭证配置
- ✅ 构建回调地址设置
- ✅ 环境变量注入（`LANGUAGE_TYPE`、`IMAGE_REPO` 等）

点击「**立即创建**」即完成应用注册。

---

## 第二步：触发构建

应用创建完成后，有两种方式触发构建：

### 方式一：自动触发（推荐）

```bash
git push origin main
```

Jenkins 收到 Webhook 后自动开始：代码拉取 → 单元测试 → 镜像构建 → 推送镜像。

### 方式二：手动触发

**CI/CD → 流水线 → 找到对应应用 → 点击「立即构建」**

---

## 第三步：创建发布单

> 如果第一步勾选了「自动部署」，构建成功后会自动发布，**可跳过此步骤**。

### 入口

**导航栏 → CI/CD → 发布管理 → 「创建发布」**

---

### 场景 A：已有应用配置（推荐路径）

> 选了应用后，命名空间、工作负载、镜像仓库全部自动继承，**只需填一个字段**：

| 字段 | 说明 | 示例 |
|------|------|------|
| **选择应用** ⭐必填 | 下拉选择刚才新建的应用 | `user-service` |
| **版本号 / 镜像标签** ⭐必填 | 本次要发布的镜像 Tag，对应构建产物 | `v1.2.3`、`abc1234`、`20240619-001` |
| 备注（选填） | 发布说明 | `修复用户登录 Bug` |

填完点「**创建发布**」，平台自动执行部署。

---

### 场景 B：新应用首次发布（无流水线）

> 如果还没创建流水线，或想直接手动指定部署目标，选择「不选应用」，展开以下字段：

| 字段 | 是否必填 | 说明 | 示例 |
|------|---------|------|------|
| **版本号 / 镜像标签** | ⭐必填 | 本次发布的版本标识 | `v1.0.0` |
| **应用名称** | ⭐必填 | 应用标识，用于发布记录展示 | `user-service` |
| **镜像地址** | ⭐必填 | 完整镜像地址（含 Tag） | `harbor.example.com/proj/user-service:v1.0.0` |
| 命名空间 | 选填 | K8s 命名空间，默认 `production` | `production`、`staging` |
| 工作负载类型 | 选填 | 默认 `Deployment` | `Deployment` / `StatefulSet` / `DaemonSet` |
| 工作负载名称 | 选填 | 留空则使用应用名 | `user-service` |
| 容器名称 | 选填 | 留空则更新第一个容器 | `app` |
| 备注 | 选填 | 发布说明 | `首次上线` |

---

## 第四步：查看发布结果

发布单提交后，在「**发布管理**」页可查看状态：

| 状态 | 含义 | 可操作 |
|------|------|--------|
| 🟡 部署中 | 正在执行部署 | 可取消 |
| 🟢 成功 | 部署完成 | 可回滚 / 重新部署 |
| 🔴 失败 | 部署失败 | 可重试 |
| 🟣 已回滚 | 已回滚到上一版本 | 可重新部署 |

---

## 日常发布（第二次及以后）

### 最简路径（2 步完成）

```
1. 发布管理 → 「创建发布」
2. 选应用 → 填版本号 → 确认
```

### 从历史记录一键重新部署

在发布记录列表中，找到目标版本，点击 **「🔄 重新部署」** 即可，无需任何输入。

---

## 快速参考：字段汇总

### 新建应用（一次性）

```
必填：应用名 + Git 仓库 + 语言类型
推荐：镜像仓库地址
可选：自动部署（集群 + 命名空间）
```

### 每次发布

```
已有应用：选应用 + 填版本号（2 个字段）
首次手动：版本号 + 应用名 + 镜像地址（3 个字段）
```

## 常见问题

**Q：不知道镜像 Tag 是什么？**
> 查看 Jenkins 构建日志末尾，或查看 Harbor 仓库中最新推送的 Tag。

**Q：发布失败了怎么办？**
> 点击发布记录的「查看详情」查看错误日志，修复后点「重试」。

**Q：怎么回滚到上一个版本？**
> 在发布记录列表中，找到上一个成功的记录，点击「🔄 重新部署」即可。

**Q：自动部署和手动发布有什么区别？**
> - **自动部署**：每次 git push → Jenkins 构建成功 → 自动触发，无需手动操作
> - **手动发布**：开发者主动选择版本号发布，适合需要审批或灰度场景
