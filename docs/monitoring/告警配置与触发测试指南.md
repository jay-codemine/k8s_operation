# 告警配置与触发测试指南

## 一、整体架构说明

```
┌──────────────┐     ┌────────────────┐     ┌───────────────┐
│  Prometheus  │────▶│  K8sOperation  │────▶│  通知渠道      │
│  (数据源)     │     │  (告警引擎)     │     │  钉钉/飞书/邮件│
└──────────────┘     └────────────────┘     └───────────────┘
       ▲                     │
       │              ┌──────┴──────┐
  node_exporter       │  告警降噪   │
  kube-state-metrics  │  静默/抑制/聚合│
                      └─────────────┘
```

**数据流向：**
1. Prometheus 采集集群指标（node_exporter + kube-state-metrics）
2. 平台定时评估告警规则（PromQL 表达式）
3. 触发的告警经过降噪过滤（静默/抑制/聚合）
4. 最终通过通知渠道发送告警消息（钉钉/飞书/企业微信/Webhook/邮件）

## 二、前置条件

### 2.1 部署 Prometheus + Exporter

```bash
# Helm 安装 kube-prometheus-stack（包含 Prometheus + node_exporter + kube-state-metrics）
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring --create-namespace \
  --set prometheus.service.type=NodePort \
  --set prometheus.service.nodePort=30091
```

验证 Prometheus 正常运行：
```bash
# 访问 Prometheus Targets 页面
curl http://<your-node-ip>:30091/targets
# 应看到 node-exporter 和 kube-state-metrics 处于 UP 状态
```

### 2.2 配置平台连接

**方式一：config.yaml（推荐）**
```yaml
Monitoring:
  Enabled: true
  PrometheusURL: "http://<prometheus-ip>:30091"
  QueryTimeout: 30
```

**方式二：数据源管理页面**
1. 访问 `监控模块 → 数据源管理`
2. 点击 `新增数据源`
3. 填写：
   - 名称: `production-prometheus`
   - 类型: `Prometheus`
   - URL: `http://<prometheus-ip>:30091`
   - 勾选"设为默认数据源"
4. 点击 `🔗 测试连通` 确认连接成功
5. 保存

> 💡 如果 config.yaml 的 PrometheusURL 为空，平台会自动使用数据源管理中的默认数据源。

## 三、配置通知渠道

### 3.1 钉钉机器人

1. 在钉钉群中添加自定义机器人：
   - 群设置 → 智能群助手 → 添加机器人 → 自定义
   - 安全设置选择 "加签"，复制 Secret

2. 平台配置：
   - 访问 `监控模块 → 通知渠道`
   - 点击 `新增渠道`
   - 类型选择 `钉钉`
   - 填写：
     - 名称: `运维告警群`
     - Webhook URL: `https://oapi.dingtalk.com/robot/send?access_token=xxxxx`
     - Secret (加签密钥): `SECxxxxx`
     - @手机号 (可选): `13800138000,13900139000`
   - 保存后点击 `📤 测试` 验证

### 3.2 飞书机器人

1. 飞书群 → 设置 → 群机器人 → 添加自定义机器人
2. 获取 Webhook URL 和签名校验的 Secret
3. 平台操作同钉钉，类型选 `飞书`

### 3.3 企业微信机器人

1. 企业微信群 → 添加群机器人
2. 获取 Webhook URL（格式: `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`）
3. 平台操作同上，类型选 `企业微信`

### 3.4 通用 Webhook

适用于自定义告警处理系统、PagerDuty、OpsGenie 等：
- 类型选 `Webhook`
- URL 填写接收端地址
- 平台会 POST JSON 格式告警数据

## 四、配置告警规则

### 4.1 通过页面配置

访问 `监控模块 → 告警规则`，点击 `新增告警规则`：

| 字段 | 示例值 | 说明 |
|------|--------|------|
| 规则名称 | CPU 使用率过高 | 告警显示名称 |
| 分组 | infrastructure | 分类分组 |
| 数据源 | production-prometheus | 关联的数据源 |
| 严重级别 | critical / warning / info | 告警等级 |
| PromQL 表达式 | `100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80` | 触发条件 |
| 持续时间 | 5m | 持续多久才触发 |
| 通知渠道 | 运维告警群 | 触发后通知到哪 |
| 摘要 | 集群 CPU 使用率超过 80% | 告警简要信息 |
| 描述 | 当前 CPU 使用率 {{ $value }}%，请及时处理 | 详细说明 |

### 4.2 常用告警规则模板

#### CPU 使用率过高
```promql
100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
```
- 级别: `warning`，持续: `5m`

#### 内存使用率过高
```promql
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100 > 85
```
- 级别: `warning`，持续: `5m`

#### 磁盘空间不足
```promql
100 - (node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"} * 100) > 90
```
- 级别: `critical`，持续: `3m`

#### Pod 重启频繁
```promql
increase(kube_pod_container_status_restarts_total[1h]) > 5
```
- 级别: `warning`，持续: `0s`（立即告警）

#### 节点 NotReady
```promql
kube_node_status_condition{condition="Ready",status="true"} == 0
```
- 级别: `critical`，持续: `2m`

#### 网络入站流量异常
```promql
sum(rate(node_network_receive_bytes_total{device!~"lo|veth.*"}[5m])) > 100*1024*1024
```
- 级别: `info`，持续: `10m`（持续 100MB/s 以上）

## 五、配置告警降噪

### 5.1 静默规则

适用场景：计划维护时临时屏蔽告警

操作：`监控模块 → 告警降噪 → 静默规则` → 新增
- 规则名称: `2024.12.25 集群升级维护`
- 匹配标签: `severity=warning` （屏蔽 warning 级别）
- 时间窗口: `2024-12-25 02:00 ~ 2024-12-25 06:00`
- 重复策略: `仅一次`

### 5.2 抑制规则

适用场景：高优先级告警触发时，自动抑制相关低优先级告警

操作：`监控模块 → 告警降噪 → 抑制规则` → 新增
- 源匹配 (高优): `severity=critical`
- 目标匹配 (被抑制): `severity=warning`
- 关联标签: `instance`（同一实例的 critical 抑制 warning）

效果：当某节点触发 critical 告警时，该节点的 warning 告警不再通知。

### 5.3 聚合规则

适用场景：相同类型告警合并，避免消息轰炸

操作：`监控模块 → 告警降噪 → 聚合规则` → 新增
- 分组标签 (Group By): `alertname, severity`
- 初次等待 (Group Wait): `30s`（收到第一条后等 30s 聚合同组）
- 分组间隔 (Group Interval): `5m`（同组有新告警时每 5 分钟发一次）
- 重复间隔 (Repeat Interval): `4h`（同样告警每 4 小时重复提醒）

## 七、告警触发验证（端到端）

### 7.1 手动触发告警（压测模拟）

```bash
# 在 K8s 集群中创建 CPU 压力 Pod
kubectl run cpu-stress --image=progrium/stress --restart=Never -- --cpu 4 --timeout 600s

# 等待 5 分钟后检查告警事件
Invoke-RestMethod -Uri "http://localhost:8080/api/v1/monitoring/alert-event?status=firing" -Headers $headers
```

### 7.2 验证通知触发

1. 确保已配置告警规则（CPU > 80%, 持续 5m）
2. 确保已配置通知渠道（钉钉群）
3. 运行压力测试后，观察：
   - 告警事件页面出现 "firing" 状态事件
   - 钉钉群收到告警消息（包含规则名称、严重级别、当前值）
4. 清除压力后等待恢复：
   ```bash
   kubectl delete pod cpu-stress
   ```
   - 如配置了"恢复通知"，钉钉群会收到 "resolved" 消息

### 7.3 验证降噪效果

**测试静默规则：**
1. 创建一条匹配当前告警的静默规则（立即生效）
2. 触发相同告警，验证不再收到通知
3. 告警事件页面仍能看到事件，但标记为"已静默"

**测试抑制规则：**
1. 创建抑制规则: critical 抑制 warning，关联标签 instance
2. 同时触发同一节点的 critical 和 warning 告警
3. 验证只收到 critical 通知，warning 被抑制

## 八、故障排查

### 8.1 监控总览数据全部为 0

**原因排查：**
1. 检查 Prometheus 是否有 targets：访问 `http://<prometheus>:30091/targets`
2. 确认 node_exporter 和 kube-state-metrics 是否 UP
3. 手动执行 PromQL 验证：
   ```promql
   up{job="node-exporter"}
   ```
   如结果为空，说明 node_exporter 未被 Prometheus 发现

**常见解决方案：**
- 安装 node_exporter: `helm install node-exporter prometheus-community/prometheus-node-exporter`
- 安装 kube-state-metrics: `helm install ksm prometheus-community/kube-state-metrics`
- 确认 ServiceMonitor 或 scrape_configs 正确配置

### 8.2 已连接但告警不触发

1. 检查告警规则是否"已启用"
2. 确认 PromQL 表达式正确（在 Prometheus 页面执行验证）
3. 检查 eval_interval 和 duration 是否合理
4. 查看后端日志: `storage/logs/app.log`

### 8.3 告警触发但未收到通知

1. 检查通知渠道是否配置正确（使用"测试发送"验证）
2. 检查告警规则是否关联了通知渠道
3. 检查是否被静默规则匹配
4. 检查钉钉机器人安全设置（IP白名单/加签密钥是否正确）

### 8.4 数据源无法连接

1. 检查 URL 是否可达: `curl <prometheus-url>/-/healthy`
2. 如有认证，确认凭据正确
3. 检查网络策略（K8s NetworkPolicy）是否放行
4. 查看后端日志中的连接错误信息

## 九、完整操作流程（Quick Start）

```
1. 部署 Prometheus + node_exporter + kube-state-metrics
2. 在平台「数据源管理」添加 Prometheus 地址并测试连通
3. 在「通知渠道」配置钉钉/飞书机器人并测试
4. 在「告警规则」创建规则（如 CPU > 80%），关联数据源和通知渠道
5. 在「告警降噪」配置聚合策略（避免消息轰炸）
6. 可选：配置静默规则（维护窗口）/ 抑制规则（降级去重）
7. 等待或手动触发告警，验证通知到达
```
