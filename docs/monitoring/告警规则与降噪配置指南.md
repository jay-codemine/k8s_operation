## 1. 模块概览

告警系统分为两大核心层：

```
┌─────────────────────────────────────────────┐
│              告警产生层                        │
│  数据源(Prometheus) → PromQL 求值 → 告警规则    │
│         → 触发事件(MonitorAlertEvent)          │
└──────────────────────┬──────────────────────┘
                       │ 告警事件
┌──────────────────────▼──────────────────────┐
│              告警降噪层                        │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 静默规则  │  │ 抑制规则  │  │ 聚合规则  │  │
│  │(时间窗口) │  │(优先级链) │  │(合并通知) │  │
│  └──────────┘  └──────────┘  └───────────┘  │
└──────────────────────┬──────────────────────┘
                       │ 最终通知
            ┌──────────▼──────────┐
            │    通知渠道发送       │
            │ 钉钉/飞书/Webhook/邮件│
            └─────────────────────┘
```

### 四类降噪规则对比

| 规则类型 | 作用 | 适用场景 |
|---------|------|---------|
| **告警规则** | 定义触发条件，基于 PromQL 评估 | 监控指标超阈值时产生告警事件 |
| **静默规则** | 按标签+时间窗口屏蔽告警通知 | 维护窗口期、已知问题临时屏蔽 |
| **抑制规则** | 高优先级告警触发时抑制低优先级告警 | 避免同一故障产生大量冗余告警 |
| **聚合规则** | 将同类告警合并为一条通知 | 告警风暴时批量通知，减少打扰 |

## 2. 告警规则（Alert Rule）

### 2.1 功能说明

告警规则基于 Prometheus PromQL 表达式定期求值，当表达式持续满足阈值条件超过 `duration` 时间后，系统生成告警事件并推送通知。

### 2.2 字段说明

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| `datasource_id` | int64 | 是 | 关联 Prometheus 数据源 ID |
| `name` | string | 是 | 规则名称，建议简洁描述告警内容 |
| `group` | string | 否 | 规则分组，默认 `default`，用于分类管理 |
| `severity` | string | 是 | 严重级别：`critical` / `warning` / `info` |
| `expr` | string | 是 | PromQL 表达式，求值结果为非空时触发 |
| `duration` | string | 否 | 持续时间，默认 `5m`，格式：`30s` / `5m` / `1h` |
| `summary` | string | 否 | 告警摘要模板，支持 `{{ $labels.xxx }}` 变量 |
| `description` | string | 否 | 告警详情模板 |
| `labels` | string | 否 | 额外标签，JSON 格式：`{"team":"ops","env":"prod"}` |
| `annotations` | string | 否 | 额外注解，JSON 格式 |
| `enabled` | bool | 否 | 是否启用，默认 `true` |
| `notify_channels` | string | 否 | 通知渠道类型，逗号分隔：`webhook,dingtalk,feishu` |
| `notify_url` | string | 否 | Webhook 通知地址 |
| `eval_interval` | int | 否 | 评估间隔（秒），默认 `60` |

### 2.3 Severity 级别说明

| 级别 | 含义 | 建议使用场景 |
|------|------|------------|
| `critical` | 紧急，服务不可用 | CPU > 95%、Pod CrashLoopBackOff、节点 NotReady |
| `warning` | 警告，需要关注 | CPU > 80%、内存 > 85%、磁盘 > 80% |
| `info` | 信息，参考性告警 | 版本变更通知、定时任务执行结果 |

### 2.4 PromQL 表达式示例

```promql
# CPU 使用率超过 80%（持续 5 分钟）
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80

# 内存使用率超过 85%
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100 > 85

# Pod 重启次数在 15 分钟内超过 5 次
rate(kube_pod_container_status_restarts_total[15m]) * 900 > 5

# 节点磁盘使用率超过 80%
(1 - node_filesystem_free_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 > 80

# 服务 HTTP 错误率超过 5%
rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
```

## 3. 告警静默（Silence Rule）

### 3.1 功能说明

静默规则在指定时间窗口内，对匹配标签的告警进行静默处理——**告警事件仍然产生，但不触发通知推送**。适用于：

- 计划内维护窗口（如深夜发布期间）
- 已知问题等待修复期间临时屏蔽
- 节假日值班降级

### 3.2 字段说明

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| `name` | string | 是 | 规则名称 |
| `type` | string | 是 | 固定填 `silence` |
| `matchers` | string | 是 | 标签匹配条件，JSON 数组，见[第6节](#6-标签匹配器说明) |
| `starts_at` | int64 | 否 | 生效开始时间（Unix 时间戳），`0` 表示立即生效 |
| `ends_at` | int64 | 否 | 生效结束时间（Unix 时间戳），`0` 表示永久 |
| `duration` | string | 否 | 持续时间（与 `ends_at` 二选一），如 `2h`/`1d` |
| `repeat_type` | string | 否 | 重复类型：`once`/`daily`/`weekly`/`cron`，默认 `once` |
| `repeat_cron` | string | 否 | Cron 表达式（`repeat_type=cron` 时有效） |
| `comment` | string | 否 | 备注说明，记录静默原因 |
| `enabled` | bool | 否 | 是否启用，默认 `true` |
| `created_by` | int64 | 是 | 创建人用户 ID（int64，非字符串） |

> **重要：** `starts_at`、`ends_at`、`created_by` 均为 **int64 类型**（Unix 时间戳或用户ID），传字符串会导致参数解析错误。

### 3.3 生效状态说明

| 状态 | 条件 |
|------|------|
| **active（生效中）** | `enabled=1` 且 `(starts_at=0 OR starts_at<=now)` 且 `(ends_at=0 OR ends_at>now)` |
| **expired（已过期）** | `ends_at>0` 且 `ends_at<=now` |
| **pending（待生效）** | `starts_at>now` |

### 3.4 API 接口

#### 获取静默规则列表

```http
GET /api/v1/monitoring/silence-rule
Authorization: Bearer <token>
```

**查询参数：**

| 参数 | 类型 | 说明 |
|-----|------|------|
| `page` | int | 页码 |
| `size` | int | 每页条数 |
| `type` | string | 规则类型过滤（`silence`） |
| `keyword` | string | 按名称或备注模糊搜索 |
| `status` | string | 状态过滤：`active`/`expired`/`all`（默认全部） |

#### 获取单条静默规则

```http
GET /api/v1/monitoring/silence-rule/:id
Authorization: Bearer <token>
```

#### 创建静默规则

```http

```

**请求体示例（维护窗口静默）：**

## 4. 告警抑制（Inhibit Rule）

### 4.1 功能说明

告警抑制实现**优先级链**：当**源告警**（高优先级）正在 `firing` 时，自动抑制与其具有相同关联标签的**目标告警**（低优先级）的通知。

**典型场景：**
- 节点宕机（`critical`）时，抑制该节点上所有 Pod 的告警（`warning`/`info`）
- 整个集群异常时，抑制单个服务的告警
- 数据库主节点故障时，抑制从节点延迟告警

### 4.2 字段说明

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| `name` | string | 是 | 规则名称 |
| `source_matchers` | string | 是 | 源告警匹配条件（触发抑制的高优先级告警），JSON 数组 |
| `target_matchers` | string | 是 | 目标告警匹配条件（被抑制的低优先级告警），JSON 数组 |
| `equal_labels` | string | 否 | 关联标签（逗号分隔），源与目标的这些标签值必须相同才触发抑制 |
| `description` | string | 否 | 规则描述 |
| `enabled` | bool | 否 | 是否启用，默认 `true` |

### 4.3 抑制逻辑流程

```
新告警事件到达
      │
      ▼
遍历所有启用的抑制规则
      │
      ▼
目标匹配？target_matchers 是否匹配新告警标签
      │ 是
      ▼
查找当前 firing 的告警事件中
是否存在匹配 source_matchers 的事件
      │ 是
      ▼
比较 equal_labels 中的标签值是否一致
      │ 全部一致
      ▼
   抑制此告警，不推送通知
```

### 4.4 API 接口

#### 获取抑制规则列表

```http
GET /api/v1/monitoring/inhibit-rule
Authorization: Bearer <token>
```

**查询参数：**

| 参数 | 类型 | 说明 |
|-----|------|------|
| `page` | int | 页码 |
| `size` | int | 每页条数 |
| `keyword` | string | 按名称或描述模糊搜索 |

#### 创建抑制规则

```http
POST /api/v1/monitoring/inhibit-rule
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体示例（节点宕机抑制 Pod 告警）：**

```json
{
  "name": "节点宕机抑制Pod告警",
  "source_matchers": "[{\"label\":\"alertname\",\"op\":\"=\",\"value\":\"NodeDown\"},{\"label\":\"severity\",\"op\":\"=\",\"value\":\"critical\"}]",
  "target_matchers": "[{\"label\":\"severity\",\"op\":\"!=\",\"value\":\"critical\"}]",
  "equal_labels": "instance,env",
  "description": "当节点宕机(critical)时，抑制该节点上的 warning/info 级别告警",
  "enabled": true
}
```

```json
  "equal_labels": "cluster,env",
  "description": "主库故障时，抑制所有复制延迟类告警",
  "enabled": true

```

## 5. 告警聚合（Aggregate Rule）

### 5.1 功能说明

告警聚合将满足匹配条件的同类告警**合并为一条通知**推送，避免告警风暴（Alert Storm）。核心机制：

- **Group Wait**（分组等待）：首次告警触发后等待一段时间再发送，收集同期告警一并推送
- **Group Interval**（分组间隔）：同一分组内已有通知的情况下，批量新告警的通知间隔
- **Repeat Interval**（重复间隔）：相同告警多久后再次推送通知（去重）

### 5.2 字段说明

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| `name` | string | 是 | 规则名称 |
| `group_by` | string | 是 | 聚合维度（逗号分隔标签名），按这些标签分组 |
| `group_wait` | string | 否 | 分组等待时间，默认 `30s` |
| `group_interval` | string | 否 | 分组间隔，默认 `5m` |
| `repeat_interval` | string | 否 | 重复间隔，默认 `4h` |
| `matchers` | string | 否 | 告警匹配条件，JSON 数组，空表示匹配所有 |
| `channel_ids` | string | 否 | 通知渠道 ID 列表（逗号分隔） |
| `enabled` | bool | 否 | 是否启用，默认 `true` |

### 5.3 时间参数说明

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `group_wait` | 收到第一条告警后，等待该时间再发通知（等待后续告警合并进来） | `30s`~`2m` |
| `group_interval` | 同一分组已发过通知后，新告警多久批量通知一次 | `5m`~`15m` |
| `repeat_interval` | 同一组告警持续 firing，多久重复推送一次提醒 | `1h`~`24h` |

**时间格式支持：** `30s`（秒）/ `5m`（分）/ `1h`（时）/ `1d`（天）

#### 创建聚合规则

## 6. 标签匹配器说明

所有规则中的 `matchers`、`source_matchers`、`target_matchers` 字段均使用统一的 JSON 数组格式：

```json
[
  {"label": "<标签名>", "op": "<操作符>", "value": "<值>"}
]
```

### 6.1 支持的操作符

| 操作符 | 含义 | 示例 |
|--------|------|------|
| `=` | 精确等于 | `{"label":"env","op":"=","value":"prod"}` |
| `!=` | 不等于 | `{"label":"severity","op":"!=","value":"info"}` |
| `=~` | 包含（字符串 contains） | `{"label":"alertname","op":"=~","value":"CPU"}` |
| `!~` | 不包含 | `{"label":"namespace","op":"!~","value":"test"}` |
| `exists` | 标签存在 | `{"label":"team","op":"exists","value":""}` |

> **注意：** `=~` 和 `!~` 为子字符串匹配（contains），而非正则表达式。

### 6.2 多条件组合

多个 matcher 之间为 **AND** 关系，所有条件同时满足才匹配：

```json
[
  {"label": "env",       "op": "=",  "value": "prod"},
  {"label": "severity",  "op": "!=", "value": "info"},
  {"label": "namespace", "op": "=~", "value": "default"}
]
```

### 6.3 空匹配器

`matchers` 为空字符串 `""` 或空数组 `"[]"` 时，匹配所有告警。

### 场景一：K8s 节点资源监控全套配置

**第一步：创建告警规则**

```bash

POST /api/v1/monitoring/alert-rule
{
  "datasource_id": 1,
  "name": "节点CPU高负载",
  "group": "node",
  "severity": "warning",
  "expr": "100 - (avg by(instance)(rate(node_cpu_seconds_total{mode=\"idle\"}[5m])) * 100) > 80",
  "duration": "5m",
  "summary": "节点 {{ $labels.instance }} CPU 使用率超过 80%",
  "enabled": true,
  "notify_channels": "dingtalk"
}

# 内存不足告警
POST /api/v1/monitoring/alert-rule
{
  "datasource_id": 1,
  "name": "节点内存不足",
  "group": "node",
  "severity": "critical",
  "expr": "(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100 > 90",
  "duration": "2m",
  "summary": "节点 {{ $labels.instance }} 内存使用率超过 90%",
```

## 附录：字段枚举值速查

### severity（告警级别）
- `critical` — 紧急
- `warning` — 警告
- `info` — 信息

### type（静默规则类型）
- `silence` — 静默

### repeat_type（重复类型）
- `once` — 仅一次（默认）
- `daily` — 每天
- `weekly` — 每周
- `cron` — 自定义 Cron

### last_eval_result（最后评估结果）
- `normal` — 正常
- `firing` — 告警中
- `pending` — 等待确认（条件满足但未超 duration）
- `error` — 评估错误

### 告警事件 status
- `firing` — 告警中
- `resolved` — 已恢复
- `silenced` — 已静默
