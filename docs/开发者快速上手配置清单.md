## 二、快速启动（本地开发模式）

### 2.1 一键启动中间件（推荐）

```bash
# 在项目根目录启动 MySQL + Redis
docker-compose up -d mysql redis
```

默认配置：
- MySQL: `127.0.0.1:3306`，密码 `admin123`，库名 `k8s-platform`
- Redis: `127.0.0.1:6379`，密码 `admin123`

> 如果端口冲突，可修改 `docker-compose.yaml` 中的端口映射和 `configs/config.yaml`。

### 2.2 启动后端

```bash
# 方式1：make run（自动编译 + 运行）
make run

# 方式2：手动运行
go build -o ./bin/k8soperation ./cmd/k8soperation
APP_CONFIG="configs/config.yaml" GIN_MODE=release ./bin/k8soperation
```

后端默认端口：**38180**

### 2.3 启动前端

```bash
cd k8s-web
npm install
npm run dev
```

前端默认端口：**5173**，代理后端到 `http://localhost:38180`

### 2.4 访问平台

- 前端地址：http://localhost:5173
- 后端 API：http://localhost:38180
- Swagger 文档：http://localhost:38180/swagger/index.html
- 默认账号：`admin` / `admin123`

## 三、核心配置文件说明

### 3.1 configs/config.yaml（后端主配置）

```yaml
Server:
  RunMode: debug          # debug/release
  Port: 38180             # 后端监听端口

Database:
  Host: 127.0.0.1
  Port: 3307              # 你的 MySQL 端口
  Username: root
  Password: "admin123"
  DBName: k8s-platform

Cache:
  Address: "127.0.0.1:6380"   # 你的 Redis 地址
  Password: "admin123"

App:
  GlobalKubeConfigPath: configs/k8s.yaml   # kubeconfig 路径
  DefaultClusterID: 9                       # 默认集群 ID（数据库中的 ID）
  AutoInitK8s: true                         # 自动初始化 K8s 连接
  AllowEmptyStart: true                     # K8s 不可用时仍可启动

Jenkins:
  URL: "http://127.0.0.1:30080/"           # Jenkins 访问地址
  Username: "ops-dev"                       # Jenkins 用户名
  APIToken: "你的API Token"                 # Jenkins API Token（非登录密码）
  GitCredentialID: "gitee-id"              # Jenkins 中 Git 凭证 ID
  RegistryCredentialID: "harbor-registry"  # Jenkins 中镜像仓库凭证 ID
  HMACSecret: "自定义签名密钥"              # 回调签名验证
  CallbackURL: "http://后端地址:38180"      # Jenkins 构建完成回调地址
```

### 3.2 configs/k8s.yaml（kubeconfig）

标准的 kubeconfig 格式文件，用于连接 K8s 集群。Docker Desktop 用户：

```bash
# 导出 Docker Desktop K8s 的 kubeconfig
kubectl config view --raw > configs/k8s.yaml
```

### 3.3 k8s-web/.env.development（前端开发配置）

```env
VITE_API_BASE=/api/v1
VITE_K8S_BASE=/api/v1/k8s
```

前端 `vite.config.js` 已内置代理，开发模式下自动转发到后端。

## 四、Jenkins 配置

### 4.1 必要插件

| 插件名 | 用途 |
|--------|------|
| Pipeline | 流水线核心 |
| Git | 代码拉取 |
| Kubernetes | K8s Pod Agent 动态构建节点 |
| HTTP Request | 平台回调通知 |
| Credentials Binding | 凭证注入 |

### 4.2 凭证配置（Jenkins → Manage Jenkins → Credentials）

| 凭证 ID | 类型 | 用途 | 内容 |
|---------|------|------|------|
| `gitee-id` | Username with password | Git 代码拉取 | Git 账号/Token |
| `harbor-registry` | Username with password | 镜像仓库推送 | 仓库用户名/密码 |
| `hmac-secret` | Secret text | 回调签名验证 | 与 config.yaml 中 HMACSecret 一致 |

### 4.3 创建 Pipeline Job（4 个通用 Job）

| Job 名称 | 对应语言 | Script Path |
|----------|---------|-------------|
| `go-pipeline` | Go | `configs/jenkins-templates/go-pipeline.groovy` |
| `java-spring-pipeline` | Java/Spring | `configs/jenkins-templates/java-spring-pipeline.groovy` |
| `frontend-pipeline` | Vue/React | `configs/jenkins-templates/frontend-pipeline.groovy` |
| `python-pipeline` | Python | `configs/jenkins-templates/python-pipeline.groovy` |

**创建步骤：**
1. Jenkins → New Item → Pipeline → 输入名称（如 `java-spring-pipeline`）
2. Pipeline → Definition: **Pipeline script from SCM**
3. SCM: Git → Repository URL: 你的平台仓库地址
4. Credentials: 选择 `gitee-id`
5. Branch: `*/main`
6. Script Path: `configs/jenkins-templates/java-spring-pipeline.groovy`
7. 保存

> 4 个 Job 都这样创建，只是名称和 Script Path 不同。

### 4.4 Jenkins API Token 获取

1. 登录 Jenkins → 右上角用户名 → Configure
2. API Token → Add new Token → Generate
3. 复制 Token 填入 `config.yaml` 的 `Jenkins.APIToken`

## 五、RBAC 权限配置

### 5.1 角色体系（三域六角色）

| 角色 | 平台域 | 集群域 | 发布域 | 适用人员 |
|------|--------|--------|--------|---------|
| super_admin | admin | admin | admin | 系统管理员 |
| platform_admin | admin | read | read | 平台管理员 |
| devops | read | admin | admin | 运维工程师 |
| **developer** | **none** | **write** | **write** | **开发工程师** |
| tester | none | read | write | 测试工程师 |
| viewer | read | read | read | 观察者 |

### 5.2 给开发者分配权限

**步骤：**
1. **创建用户** → 平台管理 → 用户管理 → 新增用户
2. **分配角色** → 权限管理 → 用户角色 → 给用户分配 `developer` 角色
3. **配置集群权限（可选）** → 权限管理 → 集群权限 → 指定该用户可访问的集群和命名空间

### 5.3 开发者权限范围

| 能力 | 说明 |
|------|------|
| ✅ 创建/触发流水线 | 自己的应用流水线 |
| ✅ 查看构建日志 | 实时日志流 |
| ✅ 查看/操作工作负载 | 限授权的命名空间内 |
| ✅ 查看 Pod 日志 | 限授权的命名空间内 |
| ✅ 查看 Service/ConfigMap | 限授权的命名空间内 |
| ❌ 管理集群节点 | 仅运维可操作 |
| ❌ 管理用户/角色 | 仅管理员可操作 |
| ❌ 删除系统级资源 | 需 admin 权限 |

## 六、快速发布操作（开发者日常）

### 6.1 创建流水线（3 步）

1. **应用信息**
   - 应用名称：如 `springboot-hello`
   - 语言类型：选择 `Java`（自动匹配 `java-spring-pipeline` Job）
   - Git 仓库：填写 HTTPS 地址（如 `https://gitee.com/xxx/xxx.git`）
   - 分支：选择要构建的分支

2. **构建配置**
   - 镜像仓库地址：如 `registry.cn-hangzhou.aliyuncs.com/your-ns/your-app`
   - Java 版本：8/11/17/21（默认 17）
   - 跳过测试：开发阶段可勾选

3. **自动部署**
   - 目标集群：自动选择（或手动切换）
   - 命名空间：选择部署目标 NS
   - 工作负载名称：默认与应用名同名

### 6.2 触发构建

- 在流水线列表点击「运行」按钮即可触发
- 支持选择分支、手动输入镜像 Tag
- 构建完成后自动更新目标 K8s Deployment 的镜像

### 6.3 查看构建状态

- 实时阶段状态：Checkout → Compile → Test → Build Image → Push → Deploy
- 点击构建记录可查看详细日志
- 构建失败会通过钉钉/飞书通知

## 七、语言类型与 Jenkins Job 映射

```
┌──────────────┬───────────────────────┬─────────────────────────────────────────────────┐
│ 语言类型      │ Jenkins Job 名称       │ Pipeline 模板路径                                │
├──────────────┼───────────────────────┼─────────────────────────────────────────────────┤
│ go           │ go-pipeline           │ configs/jenkins-templates/go-pipeline.groovy     │
│ java         │ java-spring-pipeline  │ configs/jenkins-templates/java-spring-pipeline.groovy │
│ frontend     │ frontend-pipeline     │ configs/jenkins-templates/frontend-pipeline.groovy│
│ python       │ python-pipeline       │ configs/jenkins-templates/python-pipeline.groovy │
└──────────────┴───────────────────────┴─────────────────────────────────────────────────┘
```

> 选择语言类型后，平台自动匹配对应的 Jenkins Job，无需手动填写。

## 九、故障排查

| 问题 | 原因 | 解决 |
|------|------|------|
| Jenkins 构建报 "Job不存在" | Jenkins 上 Job 名与映射不匹配 | 确保 Jenkins 上有对应名称的 Job |
| Git 分支获取失败 | 仓库 URL 格式错误 | 只填纯 URL，不要带 `git clone` 前缀 |
| 创建流水线 Duplicate entry | 同名流水线已存在 | 先删除旧流水线或换个名称 |
| 后端启动连不上 MySQL | 端口/密码不对 | 检查 `config.yaml` 中 Database 配置 |
| 前端 API 返回 401 | 登录态过期 | 重新登录，检查 JWT 配置 |
| K8s 集群连接失败 | kubeconfig 无效 | 重新导出 `kubectl config view --raw > configs/k8s.yaml` |

## 十、完整 docker-compose 一键部署

```bash
# 构建所有镜像
docker-compose build

# 启动全栈环境（MySQL + Redis + 后端 + 前端）
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止
docker-compose down
```

端口映射：
- 前端：http://localhost:80
- 后端 API：http://localhost:8080
- MySQL：localhost:3306
- Redis：localhost:6379
