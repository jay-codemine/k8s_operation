# K8sOperation 一键部署准备清单

> 目的：其他用户按本清单准备好「基础设施 + 凭证 + 密码」后，即可用 `kubectl apply -k deploy/...` 把前端 / 后端 / Jenkins 一键部署到 K8s 集群。
>
> 对应目录：`deploy/backend/`、`deploy/frontend/`、`deploy/jenkins/`、`deploy/demo-apps/`（演示业务，可选）。
>
> ⚠️ 所有 `CHANGE_ME_*` 占位、`base64` 编码值、NFS Server IP、镜像地址，**部署前必须替换为你的真实值**。

---

## 0. 架构与命名空间总览

| 命名空间 | 部署内容 | 对应目录 |
|----------|----------|----------|
| `k8soperation` | 平台后端 + 前端（Nginx 反代 `/api/` → 后端） | `deploy/backend/`、`deploy/frontend/` |
| `devops` | Jenkins Master + 动态 Agent（CI/CD 引擎） | `deploy/jenkins/` |
| `demo`（可选） | 演示业务应用（作为 CI/CD 的部署目标验证用） | `deploy/demo-apps/` |

数据流：**前端(80) → 后端(8080) → MySQL / Redis / Jenkins(8080)**；Jenkins 通过回调地址 `http://k8soperation.k8soperation.svc:8080/api/...` 反向通知平台。

## 1. 基础设施前置清单（先准备好这些）

| # | 组件 | 要求 | 说明 |
|---|------|------|------|
| 1 | **Kubernetes 集群** | v1.23+，`kubectl`、`kustomize`（或 `kubectl -k`）可用 | 有权限创建 ClusterRole / ClusterRoleBinding（平台与 Jenkins 都需要集群级 RBAC） |
| 2 | **NFS 服务器** | 供后端 3 个 PVC 使用 `ReadWriteMany`（多副本共享） | 见 §4，需预建目录并改 `deploy/backend/pv.yaml` 里的 `server` IP |
| 3 | **节点本地目录（hostPath）** | 供 Jenkins 缓存类 PV 使用 | 见 `deploy/jenkins/pv.yaml`，需在节点上存在对应目录 |
| 4 | **MySQL 8.x** | 库名默认 `k8s-platform`，字符集 `utf8mb4` | 集群内自建或外部 RDS 均可；**需先执行初始化 SQL**（见 §5） |
| 5 | **Redis** | 单机（默认）或 Cluster 模式 | 地址/密码见 §6-A 的 `REDIS_ADDRESS` / `REDIS_PASSWORD` |
| 6 | **镜像仓库账号** | 阿里云 ACR / Harbor，能拉取 `devops-be`、`devops-fe` 镜像 | 用于创建 imagePullSecret（见 §3）和 Jenkins 推镜像凭证 |
| 7 | **Ingress Controller**（可选） | 如 nginx-ingress | 不装则用 NodePort 暴露（前端默认 `30082`，Jenkins `30080`） |
| 8 | **metrics-server**（可选） | 平台资源监控（CPU/内存）需要 | 不装则监控页无数据，不影响核心功能 |

## 3. ⚠️ 必须手动创建的镜像拉取 Secret（不在 kustomize 里）

前端、后端 Deployment 都引用了 `imagePullSecrets: aliyun-registry`，但**该 Secret 不在任何 yaml 中**，必须先手动创建，否则 Pod 会 `ImagePullBackOff`：

```bash
kubectl create namespace k8soperation   # 若还没建

kubectl -n k8soperation create secret docker-registry aliyun-registry \
  --docker-server=registry.cn-hangzhou.aliyuncs.com \
  --docker-username='<你的仓库用户名>' \
  --docker-password='<你的仓库密码>'
```

## 4. 存储准备（PV / PVC）

### 4-A 后端 NFS（`deploy/backend/pv.yaml`）
在 NFS 服务器上预建目录并授权，再把文件里的 `server: 172.24.43.243` 改成你的 NFS IP：

```bash
# NFS Server 上执行
mkdir -p /data/k8soperation/{artifacts,logs,agents}
chown -R 1000:1000 /data/k8soperation      # 与容器 runAsUser=1000 对齐
```

| PVC | 容量 | 访问模式 | 挂载点 | 用途 |
|-----|------|----------|--------|------|
| `k8soperation-artifacts` | 20Gi | RWX | `/app/storage/artifacts` | CI/CD 构建制品 |
| `k8soperation-logs` | 5Gi | RWX | `/app/storage/logs` | 应用日志 |
| `k8soperation-agents` | 5Gi | RWX | `/app/storage/agents` | APM 探针文件 |

### 4-B Jenkins 存储（`deploy/jenkins/pv.yaml` / `pvc.yaml`）
`jenkins-data`（20Gi）+ 各语言构建缓存（Go / Go-build / Maven / npm / pip）。缓存类 PV 为 hostPath，需保证目标节点上目录存在（详见 `deploy/jenkins/pv.yaml` 内注释）。

## 5. 数据库初始化（务必先做）

后端 `config.yaml` 中 `SkipAutoMigrate: true`——**平台不会自动建表**，必须先手动导入初始化 SQL：

```bash
# 1) 建库
mysql -h<DB_HOST> -uroot -p -e "CREATE DATABASE \`k8s-platform\` DEFAULT CHARSET utf8mb4;"

# 2) 导入全量初始化脚本（含表结构 + 初始管理员账号等种子数据）
mysql -h<DB_HOST> -uroot -p k8s-platform < docs/sql/k8s_platform_full_init.sql
```

> 初始化脚本与升级说明详见 [`docs/sql/README.md`](../sql/README.md)。平台**默认登录账号**由该 SQL 种子数据提供。

## 6. 凭证与密码清单（核心）

### 6-A 后端 Secret：`k8soperation-secret`（文件 `deploy/backend/secret.yaml`，用 `stringData` 明文填写）

> 缺任一**必填项**，后端 Pod 无法启动。

| Key | 分类 | 必填 | 需要你提供的值 |
|-----|------|:----:|----------------|
| `DB_TYPE` | 数据库 | ✅ | 固定 `mysql` |
| `DB_USERNAME` | 数据库 | ✅ | MySQL 用户（默认 `root`） |
| `DB_PASSWORD` | 数据库 | ✅ | **MySQL 密码**（替换 `CHANGE_ME_db_password`） |
| `DB_HOST` | 数据库 | ✅ | 集群内 `mysql.k8soperation.svc.cluster.local` 或外部 MySQL 地址 |
| `DB_PORT` | 数据库 | ✅ | `3306` |
| `DB_NAME` | 数据库 | ✅ | `k8s-platform` |
| `DB_CHARSET` / `DB_PARSE_TIME` / `DB_MAX_*` | 数据库 | ✅ | 连接池参数，保持默认即可 |
| `CACHE_TYPE` | Redis | ✅ | 固定 `redis` |
| `CACHE_NAME` | Redis | ✅ | Session key 前缀（默认 `sk_sid`） |
| `REDIS_ADDRESS` | Redis | ✅ | `redis.k8soperation.svc.cluster.local:6379` 或外部地址；集群模式见 configmap 注释 |
| `REDIS_PASSWORD` | Redis | ✅ | **Redis 密码**（替换 `CHANGE_ME_redis_password`，无密码则留空） |
| `CACHE_USERNAME` | Redis | ➖ | Redis 6 ACL 用户名，一般留空 |
| `CACHE_MAX_CONNECT` / `CACHE_NETWORK` | Redis | ✅ | 保持默认 `10` / `tcp` |
| `CACHE_SECRET` | 安全 | ✅ | **会话加密盐**（替换 `CHANGE_ME_session_secret`，随机长串） |
| `JWT_SIGNING_KEY` | 安全 | ✅ | **JWT 签名密钥**（随机长串） |
| `HMAC_SECRET` | 安全/联动 | ✅ | **回调验签密钥**，须与 Jenkins `hmac-secret` **完全一致**（见 §7） |
| `KUBECONFIG_ENCRYPT_KEY` | 安全 | ✅ | **AES-256 密钥，必须正好 32 字节**（用于加密纳管集群的 kubeconfig） |
| `JENKINS_URL` | Jenkins | ✅ | `http://jenkins.devops.svc.cluster.local:8080` |
| `JENKINS_USERNAME` | Jenkins | ✅ | Jenkins 登录用户（对应 casc 里的 `ops-dev` 或 `admin`） |
| `JENKINS_API_TOKEN` | Jenkins | ✅ | **Jenkins API Token**（Jenkins 启动后在用户设置里生成，回填此处） |
| `DEFAULT_IMAGE_REGISTRY` | 可选 | ➖ | 默认镜像仓库前缀，如 `registry.cn-hangzhou.aliyuncs.com/k8s-gos` |
| `PLATFORM_FRONTEND_URL` | 可选 | ➖ | 前端公网地址（通知链接 / 审批回调用），如 `http://<节点IP>:30082` |
| `GIT_CREDENTIAL_ID` | 可选 | ➖ | 对应 Jenkins 凭证 ID，默认 `gitee-id` |
| `REGISTRY_CREDENTIAL_ID` | 可选 | ➖ | 对应 Jenkins 凭证 ID，默认 `harbor-registry` |
| `HMAC_CREDENTIAL_ID` | 可选 | ➖ | 对应 Jenkins 凭证 ID，默认 `hmac-secret` |
| `GIT_USERNAME` | 可选/联动 | ➖ | 平台侧「检测仓库 / 获取分支」访问私有仓库用；Gitee 用 `oauth2`，GitHub 可留空 |
| `GIT_TOKEN` | 可选/联动 | ➖ | Git 密码或 Personal Access Token，建议与 Jenkins `gitee-password` 同源（见 §7） |
| `ENABLE_DINGTALK` / `DINGTALK_WEBHOOK` | 可选 | ➖ | 钉钉通知，默认关闭 |
| `ENABLE_FEISHU` / `FEISHU_WEBHOOK` / `FEISHU_SECRET` | 可选 | ➖ | 飞书通知，默认关闭 |
| `LDAP_*`（configmap 引用） | 可选 | ➖ | 启用 LDAP 时才需要，默认 `LDAP.Enabled: false` |

| Key | 含义 | 必填 | 需要你提供的值 |
|-----|------|:----:|----------------|

## 7. 🔗 三处必须「保持一致」的联动凭证

部署前重点核对，否则 CI/CD 回调 / 拉代码 / 推镜像会失败：

| 联动项 | 后端（k8soperation-secret） | Jenkins（jenkins-secret / casc） | 说明 |
|--------|------------------------------|-----------------------------------|------|
| **HMAC 验签** | `HMAC_SECRET` | `hmac-secret`（casc id `hmac-secret`） | 两边**必须完全相同**，否则流水线回调被拒 |
| **Git 凭证** | `GIT_USERNAME` / `GIT_TOKEN` | `gitee-username` / `gitee-password`（casc id `gitee-id`） | 建议同源同值 |
| **镜像仓库** | imagePullSecret `aliyun-registry` + `DEFAULT_IMAGE_REGISTRY` | `registry-username` / `registry-password`（casc id `harbor-registry`） | 同一仓库账号，拉/推一致 |

## 8. 一键部署步骤（按顺序执行）

```bash
# ── 第 0 步：改配置 ──────────────────────────────
#   ① deploy/backend/secret.yaml    ← 替换所有 CHANGE_ME_*
#   ② deploy/backend/pv.yaml        ← 改 NFS server IP
#   ③ deploy/jenkins/secret.yaml    ← 替换 base64 占位值
#   ④ 确认镜像地址（若用自建仓库）

# ── 第 1 步：数据库初始化（见 §5）────────────────
mysql -h<DB_HOST> -uroot -p k8s-platform < docs/sql/k8s_platform_full_init.sql

# ── 第 2 步：镜像拉取 Secret（见 §3）─────────────
kubectl create namespace k8soperation
kubectl -n k8soperation create secret docker-registry aliyun-registry \
  --docker-server=registry.cn-hangzhou.aliyuncs.com \
  --docker-username='<user>' --docker-password='<pass>'

# ── 第 3 步：NFS / hostPath 目录准备（见 §4）─────

# ── 第 4 步：部署 Jenkins（独立 namespace: devops）──
kubectl apply -k deploy/jenkins/
kubectl -n devops rollout status statefulset/jenkins
#   Jenkins 起来后登录，生成 API Token 回填后端 secret 的 JENKINS_API_TOKEN

# ── 第 5 步：部署后端 ────────────────────────────
kubectl apply -k deploy/backend/
kubectl -n k8soperation rollout status deployment/k8soperation

# ── 第 6 步：部署前端 ────────────────────────────
kubectl apply -k deploy/frontend/
kubectl -n k8soperation rollout status deployment/k8soperation-web

# ── （可选）一键部署前后端 ──────────────────────
# kubectl apply -k deploy/            # 同时含 backend + frontend
# kubectl apply -k deploy/demo-apps/  # 部署演示业务到 demo 命名空间
```

## 10. 部署后验证清单

```bash
# 1) 所有 Pod Running
kubectl -n k8soperation get pods
kubectl -n devops get pods

# 2) PVC 全部 Bound
kubectl -n k8soperation get pvc
kubectl -n devops get pvc

# 3) 后端健康检查
kubectl -n k8soperation exec deploy/k8soperation -- wget -qO- localhost:8080/healthz/ready

# 4) 前端可访问
curl http://<节点IP>:30082/health      # 期望返回 ok

# 5) 浏览器打开前端 → 用 init.sql 中的初始账号登录
```

| 检查项 | 期望 |
|--------|------|
| `aliyun-registry` Secret 已创建 | 否则 Pod `ImagePullBackOff` |
| 后端 3 个 PVC + Jenkins PVC | 全部 `Bound` |
| 后端 Pod | `Running` 且 `/healthz/ready` 返回 200 |
| 前端 Pod | `Running`，`/health` 返回 `ok` |
| Jenkins | `30080` 可登录，casc 凭证 `gitee-id`/`harbor-registry`/`hmac-secret` 已加载 |
| HMAC / Git / 镜像凭证 | 后端与 Jenkins 三处一致（§7） |

## 11. 常见坑速查

| 现象 | 排查方向 |
|------|----------|
| Pod `ImagePullBackOff` | 未建 `aliyun-registry`（§3）或镜像地址/账号错误 |
| 后端 `CrashLoopBackOff` | secret 有 `CHANGE_ME_*` 未替换；`KUBECONFIG_ENCRYPT_KEY` 不是 32 字节；DB/Redis 连不上 |
| 就绪探针一直失败 | `DB_HOST`/`REDIS_ADDRESS` 不通；外部/公网 MySQL 把 `Server.ReadinessTimeout` 调到 2~3s |
| PVC 一直 `Pending` | NFS server IP 未改 / 目录不存在 / 无 `ReadWriteMany` 供给能力 |
| 登录后接口 401/403 | `JWT_SIGNING_KEY` 变更导致旧 token 失效；重新登录 |
| 流水线回调失败 | 后端 `HMAC_SECRET` 与 Jenkins `hmac-secret` 不一致（§7） |
| 拉取私有仓库分支失败 | 后端 `GIT_USERNAME`/`GIT_TOKEN` 未配置或与 Jenkins 凭证不一致 |
| 数据库表不存在 | 未执行 `docs/sql/k8s_platform_full_init.sql`（`SkipAutoMigrate: true`） |
