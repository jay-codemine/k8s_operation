# K8sOperation 前端虚拟机部署指南

> 适用于：Linux 虚拟机 + Nginx + systemd 管理模式（非容器/K8s 部署）

---

## 一、环境要求

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| Nginx | >= 1.20 | 静态托管 + 反向代理 |
| Node.js | >= 20.19 | 仅构建时需要，服务器可不安装 |
| 后端服务 | 同机 :8080 | K8sOperation Go 后端 |

---

## 二、前端构建

在开发机上执行（Mac / Linux 均可）：

```bash
cd k8s-web

# 安装依赖
npm install

# 构建生产包
npm run build
```

构建完成后生成 `dist/` 目录，包含所有静态文件。

---

## 三、部署目录结构

将 `dist/` 目录上传到服务器：

```
/opt/k8soperation/
├── k8soperation          # 后端二进制
├── config.yaml           # 后端配置文件
├── storage/logs/         # 日志目录
└── dist/                 # 前端静态文件
    ├── index.html
    ├── assets/
    │   ├── index-xxxx.js
    │   ├── index-xxxx.css
    │   └── ...
    └── favicon.ico
```

```bash
# 上传到服务器
scp -r k8s-web/dist/* root@<SERVER_IP>:/opt/k8soperation/dist/
```

## 四、Nginx 配置

### 4.1 创建配置文件

```bash
vim /etc/nginx/conf.d/k8soperation.conf
```

写入以下内容：

```nginx
upstream backend {
    server 127.0.0.1:8080;    # 后端 Go 服务（同机部署）
}

server {
    listen 80;
    server_name _;            # 改成你的域名或 IP

    root /opt/k8soperation/dist;
    index index.html;

    # ========== Gzip 压缩 ==========
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/javascript
               application/json application/javascript
               application/xml image/svg+xml;

    # ========== 静态资源缓存（30天） ==========
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # ========== API 反向代理 → 后端 ==========
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持（容器终端、日志流）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 长连接超时（1小时，支持终端会话）
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;

        # 文件上传大小限制
        client_max_body_size 200m;
    }

    # ========== Swagger 文档代理 ==========
    location /swagger/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
    }

    # ========== 健康检查 ==========
    location /health {
        access_log off;
        return 200 "ok";
        add_header Content-Type text/plain;
    }

    # ========== Vue Router History 模式 ==========
    # 所有未匹配的路由返回 index.html，由前端路由处理
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ========== 安全响应头 ==========
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
}
```

### 4.2 验证并重载

```bash
# 检查语法
nginx -t

# 重载配置
systemctl reload nginx
```

## 五、配置说明

### 5.1 关键路由对照表

| 请求路径 | 处理方 | 说明 |
|----------|--------|------|
| `/api/*` | 后端 Go :8080 | 所有 API 请求反向代理 |
| `/swagger/*` | 后端 Go :8080 | Swagger 接口文档 |
| `*.js, *.css, 图片` | Nginx 直接返回 | 静态资源 + 30天强缓存 |
| 其他路径 | Nginx → `index.html` | Vue Router History 模式 |

### 5.2 WebSocket 支持

前端使用 WebSocket 连接的功能：
- **容器终端** (xterm.js)
- **Pod 日志实时流**

Nginx 配置中已包含：
```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 3600s;
```

### 5.3 前端环境变量

前端构建时读取 `.env` 文件：

```env
VITE_API_BASE=/api/v1           # 后端 API 基础路径
VITE_API_BASE_KUBE=/api/v1/k8s  # K8s API 基础路径
```

这些值在 `npm run build` 时已编译进 js 包中，部署后无需修改。前端所有 API 请求走相对路径 `/api/xxx`，由 Nginx 自动代理到后端。

## 六、HTTPS 配置（可选）

如需启用 HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate     /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # ... 其余配置与上面 HTTP 相同 ...
}

# HTTP 自动跳转 HTTPS
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

## 七、前端更新流程

每次前端有代码更新时：

```bash
# 1. 本地构建
cd k8s-web && npm run build

# 2. 上传新 dist 到服务器（覆盖旧文件）
scp -r dist/* root@<SERVER_IP>:/opt/k8soperation/dist/

# 3. 无需重启任何服务（Nginx 直接读取新文件）
# 如需清除缓存，可以：
# nginx -s reload
```

> 注意：Vite 构建的 JS/CSS 文件名带 hash，浏览器会自动加载新版本，无需手动清缓存。

## 八、常见问题

### Q1: 页面刷新 404

**原因**：Nginx 未配置 `try_files` 兜底
**解决**：确保 `location /` 中有：
```nginx
try_files $uri $uri/ /index.html;
```

### Q2: API 请求 502 Bad Gateway

**原因**：后端服务未启动或端口不对
**排查**：
```bash
# 检查后端是否运行
systemctl status k8soperation

# 检查端口监听
ss -tlnp | grep 8080
```

### Q3: WebSocket 连接断开

**原因**：Nginx 默认 60s 超时
**解决**：已在配置中设置 `proxy_read_timeout 3600s`

### Q4: 文件上传失败 (413)

**原因**：Nginx 默认限制 1MB
**解决**：已在配置中设置 `client_max_body_size 200m`

## 九、完整部署一键脚本

```bash
#!/bin/bash
# deploy-frontend.sh - 前端一键部署脚本

DEPLOY_DIR="/opt/k8soperation"
NGINX_CONF="/etc/nginx/conf.d/k8soperation.conf"

echo ">>> 创建目录"
mkdir -p ${DEPLOY_DIR}/dist

echo ">>> 复制前端文件"
cp -r dist/* ${DEPLOY_DIR}/dist/

echo ">>> 设置权限"
chmod -R 755 ${DEPLOY_DIR}/dist

echo ">>> 检查 Nginx 配置"
nginx -t
if [ $? -ne 0 ]; then
    echo "ERROR: Nginx 配置检查失败"
    exit 1
fi

echo ">>> 重载 Nginx"
systemctl reload nginx

echo "✅ 前端部署完成"
echo "   访问地址: http://$(hostname -I | awk '{print $1}')"
```
