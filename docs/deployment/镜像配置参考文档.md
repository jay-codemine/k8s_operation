## ⚙️ 镜像拉取策略

### Pipeline 模板

**策略**: `imagePullPolicy: Always`

**原因**:
1. 确保始终拉取最新镜像
2. 避免 K8s 节点缓存导致架构不匹配
3. 解决 `exec format error` 问题

### 后端服务

**策略**: `imagePullPolicy: Always`

**配置文件**: `deploy/backend/deployment.yaml`

### Init Container

**策略**: `imagePullPolicy: IfNotPresent`

**说明**: init container 使用 Alpine 官方镜像，不需要 Always 拉取

## 🔄 镜像更新流程

### 1. 更新 Pipeline 模板

```bash
# 编辑模板文件
vi configs/jenkins-templates/go-pipeline.groovy

# 提交并推送
git add configs/jenkins-templates/
git commit -m "update: Pipeline 模板镜像地址"
git push origin main
git push gitlab main
```

### 2. 更新 Dockerfile 模板

```bash
# 编辑模板文件
vi configs/dockerfile-templates/Dockerfile.golang

# 提交并推送
git add configs/dockerfile-templates/
git commit -m "update: Dockerfile 模板镜像地址"
git push origin main
git push gitlab main
```

### 3. 构建后端镜像

```bash
# 构建 amd64 架构镜像
docker buildx build --platform linux/amd64 \
  -f docker/backend/Dockerfile \
  -t registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-be:<version> \
  --push .
```

### 4. 更新 deployment.yaml

```bash
# 编辑 deployment.yaml
vi deploy/backend/deployment.yaml

# 提交并推送
git add deploy/backend/deployment.yaml
git commit -m "update: deployment.yaml 使用 <version> 镜像"
git push origin main
git push gitlab main
```

### 5. 应用 K8s 部署

```bash
kubectl apply -f deploy/backend/deployment.yaml
```

## ⚠️ 注意事项

### 架构匹配

- **所有镜像必须为 amd64 架构**
- Mac（Apple Silicon）本地构建时需指定 `--platform linux/amd64`
- 使用 `docker inspect <image> --format '{{.Architecture}}'` 验证架构

### 版本升级

- Pipeline 模板更新后，**新建的 Pod** 会自动使用新镜像
- 已运行的 Pod 不受影响
- 后端服务更新需手动执行 `kubectl apply`

### 镜像缓存

- K8s 节点可能缓存旧镜像
- 使用 `imagePullPolicy: Always` 可避免缓存问题
- 如需强制刷新，可删除旧镜像：`docker rmi <image>`
