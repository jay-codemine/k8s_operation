# K8sOperation 配置文件与环境变量说明

## 一、配置架构概览

```
┌─────────────────────────────────────────────────────────────────────┐
│                      配置加载优先级（从高到低）                        │
├─────────────────────────────────────────────────────────────────────┤
│  1. 环境变量 APP_CONFIG 指定绝对路径（容器部署推荐）                   │
│  2. 相对路径 configs/config.yaml（本地开发 / VM 部署）                │
│  3. 绝对路径 /app/configs/config.yaml（容器内兜底）                   │
│  4. 可执行文件同级 configs/config.yaml                               │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、两种部署模式对比

| 维度 | K8s 容器部署 | 虚拟机 / 裸机部署 |
|------|-------------|-----------------|
| 配置文件来源 | ConfigMap 挂载到 `/app/configs/config.yaml` | 直接放在 `configs/config.yaml` |
| 敏感信息存储 | Secret（`k8soperation-secret`） | 直接写在 config.yaml 明文中 |
| 密码写法 | `Password: "${DB_PASSWORD}"` 占位符 | `Password: "real_password"` 明文 |
| 环境变量展开 | 自动：代码启动时 `expandEnvInViper()` | 不需要（无占位符则不触发） |
| 服务管理 | Deployment + Pod | systemd service |

## 三、K8s 部署配置流程

### 3.1 敏感信息注入链路

```
Secret (k8soperation-secret)
    │  stringData:
    │    DB_PASSWORD: "super<>foxess"
    │    REDIS_PASSWORD: "xxx"
    │    JWT_SIGNING_KEY: "xxx"
    │    JENKINS_URL / USERNAME / API_TOKEN
    │    HMAC_SECRET / KUBECONFIG_ENCRYPT_KEY
    │
    │  ← Deployment env.valueFrom.secretKeyRef
    ▼
Pod 容器环境变量
    │  DB_PASSWORD=super<>foxess
    │  REDIS_PASSWORD=xxx
    │  APP_CONFIG=/app/configs/config.yaml
    │
    │  ← ConfigMap 挂载 config.yaml（含 ${} 占位符）
    ▼
代码 setting.go: expandEnvInViper()
    │  遍历所有配置项
    │  发现 "${DB_PASSWORD}" → os.ExpandEnv → "super<>foxess"
    ▼
global.DatabaseSetting.Password = "super<>foxess" ✅
```

### 3.2 相关文件

| 文件 | 作用 |
|------|------|
| `deploy/backend/secret.yaml` | K8s Secret，存放数据库密码、Redis 密码、JWT 密钥等 |
| `deploy/backend/configmap.yaml` | K8s ConfigMap，存放 config.yaml（使用 `${ENV}` 占位符） |
| `deploy/backend/deployment.yaml` | Deployment，定义环境变量注入和卷挂载 |

### 3.3 ConfigMap 中的占位符

ConfigMap 中敏感配置使用 `${ENV_VAR}` 格式占位：

```yaml
Database:
  Password: "${DB_PASSWORD}"        # 从 Secret 注入

Cache:
  Password: "${REDIS_PASSWORD}"     # 从 Secret 注入
  Secret: "${CACHE_SECRET}"         # 从 Secret 注入

App:
  JWTSigningKey: "${JWT_SIGNING_KEY}"

Jenkins:
  URL: "${JENKINS_URL}"
  Username: "${JENKINS_USERNAME}"
  APIToken: "${JENKINS_API_TOKEN}"
  HMACSecret: "${HMAC_SECRET}"
  DingTalkWebhook: "${DINGTALK_WEBHOOK}"

Security:
  KubeConfigEncryptKey: "${KUBECONFIG_ENCRYPT_KEY}"
```

### 3.4 Deployment 环境变量定义

```yaml
env:
  - name: APP_CONFIG
    value: "/app/configs/config.yaml"
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: k8soperation-secret
        key: DB_PASSWORD
  - name: REDIS_PASSWORD
    valueFrom:
      secretKeyRef:
        name: k8soperation-secret
        key: REDIS_PASSWORD
  # ... 其他 Secret 引用
```

## 四、虚拟机部署配置

### 4.1 目录结构

```
/opt/k8soperation/
├── k8soperation          # 二进制可执行文件
├── configs/
│   ├── config.yaml       # 主配置（直接写明文密码）
│   └── k8s.yaml          # K8s 集群 kubeconfig（可选）
└── storage/
    └── logs/             # 日志输出目录
```

### 4.2 配置文件示例（虚拟机版）

虚拟机上**直接写真实值**，不需要 `${}` 占位符：

```yaml
Server:
  RunMode: release
  Port: 8080
  ReadTimeout: 3600
  WriteTimeout: 3600

Database:
  DBType: mysql
  Username: root
  Password: "your_real_password"     # ← 直接写明文
  Host: 127.0.0.1
  Port: 3306
  DBName: k8s-platform
  Charset: utf8mb4
  ParseTime: true
  MaxIdleConns: 10
  MaxOpenConns: 100
  MaxLifeSeconds: 300

Cache:
  Type: redis
  Address: 127.0.0.1:6379
  Password: "your_redis_password"    # ← 直接写明文
  MaxConnect: 10
  Network: tcp
  Secret: "your_cache_secret"

App:
  LogLevel: info
  JWTSigningKey: "your_jwt_key_at_least_32_chars!!"
  # ... 其他配置
```

### 4.3 systemd Service 配置

```ini
# /etc/systemd/system/k8soperation.service
[Unit]
Description=K8sOperation Platform
After=network.target mysql.service redis.service

[Service]
Type=simple
User=root
WorkingDir=/opt/k8soperation
ExecStart=/opt/k8soperation/k8soperation
Restart=always
RestartSec=5

# 可选：通过环境变量指定配置文件路径
# Environment=APP_CONFIG=/opt/k8soperation/configs/config.yaml

[Install]
WantedBy=multi-user.target
```

### 4.4 启动命令

```bash
sudo systemctl daemon-reload
sudo systemctl enable k8soperation
sudo systemctl start k8soperation
sudo systemctl status k8soperation

# 查看实时日志
sudo journalctl -u k8soperation -f
```

## 五、配置加载代码说明

核心代码位于 `pkg/setting/setting.go`：

```go
func NewSetting() (*Setting, error) {
    // 优先级1：环境变量 APP_CONFIG 指定路径
    if configPath := os.Getenv("APP_CONFIG"); configPath != "" {
        vp := viper.New()
        vp.SetConfigFile(configPath)
        vp.ReadInConfig()
        expandEnvInViper(vp)  // 展开 ${} 占位符
        return &Setting{vp: vp}, nil
    }

    // 优先级2-4：按路径搜索 config.yaml
    vp := viper.New()
    vp.SetConfigName("config")
    vp.AddConfigPath("configs")           // 相对路径（本地开发/VM）
    vp.AddConfigPath("/app/configs")      // 容器绝对路径
    // + 可执行文件同级 configs/
    vp.SetConfigType("yaml")
    vp.ReadInConfig()
    expandEnvInViper(vp)  // 展开 ${} 占位符
    return &Setting{vp: vp}, nil
}

// expandEnvInViper 将 "${DB_PASSWORD}" → 实际环境变量值
func expandEnvInViper(vp *viper.Viper) {
    for _, key := range vp.AllKeys() {
        if strVal, ok := vp.Get(key).(string); ok {
            if strings.Contains(strVal, "${") {
                vp.Set(key, os.ExpandEnv(strVal))
            }
        }
    }
}
```

## 七、Dockerfile 与配置路径

```dockerfile
FROM alpine:3.20

# 创建非 root 用户（UID=1000）
RUN addgroup -g 1000 app && adduser -D -u 1000 -G app app

WORKDIR /app
RUN mkdir -p /app/storage/logs /app/configs

COPY bin/devops-be /app/devops-be
RUN chmod +x /app/devops-be && chown -R app:app /app
USER app

# 关键环境变量
ENV GIN_MODE=release
ENV APP_CONFIG=/app/configs/config.yaml    # ← 告诉代码配置文件位置
ENV K8S_CONFIG=/app/configs/k8s.yaml

EXPOSE 8080
ENTRYPOINT ["/app/devops-be"]
```

## 八、常见问题

### Q1: 容器启动报 `Config File "config" Not Found in "[/configs]"`

**原因**：未设置 `APP_CONFIG` 环境变量，且容器工作目录不是 `/app`。

**解决**：确保 Deployment 中设置了：
```yaml
env:
  - name: APP_CONFIG
    value: "/app/configs/config.yaml"
```
并且 ConfigMap 正确挂载到该路径。

### Q2: 数据库连接失败，密码是 `${DB_PASSWORD}` 字面量

**原因**：Secret 未正确注入环境变量，或 Deployment 中缺少 `secretKeyRef` 定义。

**排查**：
```bash
kubectl exec -it <pod-name> -n k8soperation -- env | grep DB_PASSWORD
```
如果输出为空或不对，检查 Secret 和 Deployment 的 env 配置。

### Q3: 虚拟机部署时 config.yaml 中要不要写 `${}`？

**不需要**。虚拟机上直接写明文密码即可，`${}` 语法仅用于 K8s ConfigMap + Secret 的分离式配置。
