# K8sOperation 前端一键部署指南

## 概述

本文档介绍如何将 K8sOperation 前端（Vue 3 + Vite + Nginx）一键构建镜像并部署到 K8s 集群。

**部署架构：**
```
用户浏览器 → Ingress/NodePort → k8soperation-web (Nginx)
                                       │
                                       ├── 静态资源 (dist/)
                                       └── /api/* 反代 → k8soperation (Go API :8080)
```

---

## 前置条件

| 工具 | 最低版本 | 用途 |
|------|---------|------|
| Docker | 20+ | 构建镜像 |
| kubectl | 1.24+ | 部署到 K8s |
| K8s 集群 | 1.24+ | 运行环境 |

确保后端已部署（`k8soperation` Service 存在且可访问）。

---

## 快速开始（一键部署）

### 方式一：使用脚本

```bash
# 最简部署（构建 + 推送 + 部署）
bash scripts/deploy-frontend.sh

# 指定版本号
IMAGE_TAG=v1.2.0 bash scripts/deploy-frontend.sh

# 指定 Ingress 域名
EXPOSURE=ingress DOMAIN=k8sop.mycompany.com bash scripts/deploy-frontend.sh

# 使用 NodePort 暴露
EXPOSURE=nodeport NODE_PORT=30081 bash scripts/deploy-frontend.sh

# 跳过构建，直接部署已有镜像
SKIP_BUILD=true IMAGE_TAG=v1.2.0 bash scripts/deploy-frontend.sh
```

### 方式二：使用 Kustomize（前后端一起）

```bash
# 一键部署前端 + 后端 + 所有资源
kubectl apply -k deploy/
```

## 手动分步部署

### Step 1: 构建前端镜像

```bash
# 在项目根目录执行
docker build -f k8s-web/Dockerfile -t registry.cn-hangzhou.aliyuncs.com/k8s-gos/k8soperation-web:latest ./k8s-web
```

构建过程：
1. **Stage 1 (Node)**: `npm ci` 安装依赖 → `npm run build` 编译出 `dist/`
2. **Stage 2 (Nginx)**: 将 `dist/` 放入 Nginx，配置反向代理

### Step 2: 推送到镜像仓库

```bash
# 登录镜像仓库
docker login registry.cn-hangzhou.aliyuncs.com

# 推送
docker push registry.cn-hangzhou.aliyuncs.com/k8s-gos/k8soperation-web:latest
```

### Step 3: 部署到 K8s

```bash
# 部署前端（Deployment + Service + Ingress）
kubectl apply -f deploy/frontend-deployment.yaml

# 查看状态
kubectl -n k8soperation get pods -l app.kubernetes.io/name=k8soperation-web
```

### Step 4: 验证

```bash
# 查看 Pod 状态
kubectl -n k8soperation get pods -l app.kubernetes.io/name=k8soperation-web

# 临时端口转发测试
kubectl -n k8soperation port-forward svc/k8soperation-web 8080:80

# 浏览器访问 http://localhost:8080
```

## 配置参数说明

### 脚本环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `NAMESPACE` | `k8soperation` | K8s 命名空间 |
| `IMAGE_REGISTRY` | `registry.cn-hangzhou.aliyuncs.com/k8s-gos` | 镜像仓库 |
| `IMAGE_NAME` | `k8soperation-web` | 镜像名 |
| `IMAGE_TAG` | `latest` | 镜像标签 |
| `EXPOSURE` | `clusterip` | 暴露方式：`clusterip` / `nodeport` / `ingress` |
| `DOMAIN` | `k8sop.example.com` | Ingress 域名 |
| `NODE_PORT` | `30081` | NodePort 端口 |
| `BACKEND_URL` | `http://k8soperation.k8soperation.svc:8080` | 后端 API 地址 |
| `REPLICAS` | `2` | 副本数 |
| `SKIP_BUILD` | `false` | 是否跳过镜像构建 |

### 运行时环境变量

| 变量 | 说明 |
|------|------|
| `API_BACKEND_URL` | 后端 API 地址（Nginx 反代目标），默认 `http://k8soperation-api:8080` |

## 运维操作

### 滚动更新

```bash
# 方式一：直接更新镜像
kubectl -n k8soperation set image deploy/k8soperation-web \
    web=registry.cn-hangzhou.aliyuncs.com/k8s-gos/k8soperation-web:v1.3.0

# 方式二：重新执行脚本
IMAGE_TAG=v1.3.0 SKIP_BUILD=true bash scripts/deploy-frontend.sh

# 查看更新状态
kubectl -n k8soperation rollout status deploy/k8soperation-web
```

### 回滚

```bash
# 回滚到上一个版本
kubectl -n k8soperation rollout undo deploy/k8soperation-web

# 回滚到指定版本
kubectl -n k8soperation rollout history deploy/k8soperation-web
kubectl -n k8soperation rollout undo deploy/k8soperation-web --to-revision=2
```

### 扩缩容

```bash
# 扩容到 3 副本
kubectl -n k8soperation scale deploy/k8soperation-web --replicas=3
```

### 查看日志

```bash
# 查看所有前端 Pod 日志
kubectl -n k8soperation logs -f -l app.kubernetes.io/name=k8soperation-web

# 查看指定 Pod
kubectl -n k8soperation logs -f k8soperation-web-xxx-yyy
```

### 卸载前端

```bash
kubectl -n k8soperation delete deploy,svc,ingress k8soperation-web
```

## 部署对比（前端 vs 后端）

| 对比项 | 后端 | 前端 |
|--------|------|------|
| 脚本 | `scripts/deploy-k8s.sh` | `scripts/deploy-frontend.sh` |
| Dockerfile | `Dockerfile` (根目录) | `k8s-web/Dockerfile` |
| K8s 配置 | `deploy/deployment.yaml` | `deploy/frontend-deployment.yaml` |
| 暴露端口 | 8080 | 80 |
| 副本数 | 1（有状态 PVC） | 2+（无状态） |
| 健康检查 | `/healthz/live` | `/health` |
| ConfigMap | 需要（config.yaml） | 不需要 |
| Secret | 需要（数据库密码等） | 不需要 |
| PVC | 需要（日志+制品） | 不需要 |

## 常见问题

### Q: 前端访问白屏 / 404

- 确认 Nginx 配置了 `try_files $uri $uri/ /index.html`（已内置）
- 确认 Ingress 的 path 配置正确

### Q: API 请求 502 / 连接后端失败

- 确认后端 Service 正常运行：`kubectl -n k8soperation get svc k8soperation`
- 确认 `API_BACKEND_URL` 环境变量指向正确的后端地址
- 查看 Nginx 日志：`kubectl -n k8soperation logs deploy/k8soperation-web`

### Q: 如何自定义后端地址

部署时通过环境变量覆盖：

```bash
BACKEND_URL=http://my-backend.default.svc:8080 bash scripts/deploy-frontend.sh
```

或在 `deploy/frontend-deployment.yaml` 中修改：

```yaml
env:
  - name: API_BACKEND_URL
    value: "http://your-backend-address:8080"
```

### Q: 本地 Docker 验证

```bash
# 构建
docker build -f k8s-web/Dockerfile -t k8soperation-web:dev ./k8s-web

# 运行（连接本地后端）
docker run -d --name k8soperation-web \
    -p 80:80 \
    -e API_BACKEND_URL=http://host.docker.internal:8080 \
    k8soperation-web:dev

# 浏览器访问 http://localhost
```
