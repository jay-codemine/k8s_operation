# 登录认证流程详细说明

## 一、架构概览

本平台采用 **JWT (JSON Web Token) + Session 双重机制** 的认证方案：

- **主认证**：JWT Bearer Token（无状态，前端通过 Header 携带）
- **辅助会话**：Redis Session（用于服务端状态跟踪，如审计日志）
- **Token 续签**：前端自动刷新机制（401 → refresh → 重试）

```
┌──────────────┐     POST /auth/login        ┌──────────────────┐
│   前端 Vue   │ ─────────────────────────────▶│   Gin Handler    │
│  (Login.vue) │                               │   (login.go)     │
└──────┬───────┘                               └────────┬─────────┘
       │                                                │
       │  ◀──── { token, user } ─────────────────────────┘
       │                                       ┌────────────────────┐
       │     每次请求 Authorization: Bearer xxx │  AuthJWT 中间件     │
       │ ──────────────────────────────────────▶│  (middlewares/     │
       │                                       │   auth.go)         │
       │  ◀──── 200 / 401 ────────────────────── └────────────────────┘
       │
       │  401 时自动 POST /auth/refresh
       │ ──────────────────────────────────────▶ Refresh Handler
       │  ◀──── { new_token } ──────────────────
```

## 三、JWT 配置参数

在 `configs/config.yaml` 的 `App` 段中配置：

```yaml
App:
  JWTSigningKey: "your-secret-key"       # HS256 签名密钥
  JWTExpireTime: 120000                   # Token 过期时间（分钟）
  JWTMaxRefreshTime: 86400                # 最大可刷新窗口（分钟，从签发时间起算）
```

对应代码读取位置：`pkg/setting/section.go`

```go
type AppSection struct {
    JWTExpireTime     int    // Token 过期时间（分钟）
    JWTSigningKey     string // 签名密钥
    JWTMaxRefreshTime int    // 最大可刷新时间（分钟）
}
```

## 四、登录流程详解

### 4.1 前端发起登录

**文件**：`k8s-web/src/views/auth/Login.vue`

```javascript
// 1. 用户输入用户名密码，点击登录
const handleSubmit = async () => {
  const res = await login({ username, password })
  const { token, user } = res.data
  
  // 2. 存储到 localStorage 或 sessionStorage（取决于"记住我"）
  storeAuth(token, user, remember)
}
```

**存储策略**：
- 勾选「记住我」→ `localStorage`（浏览器关闭后仍保留）
- 未勾选 → `sessionStorage`（关闭标签页即失效）

### 4.2 后端登录处理

**文件**：`internal/app/controllers/api/v1/auth/login.go`

完整流程：

```
POST /api/v1/auth/login  { username, password }
        │
        ▼
┌─ 1. 参数校验（govalidator）─────────────────────────┐
│   验证 username/password 非空、格式合法              │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 2. 查询用户 ──────────────────────────────────────┐
│   svc.UserLogin(param)                              │
│   → dao.UserGetByName(username)                     │
│   → SELECT * FROM user WHERE username = ?           │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 3. 用户状态检查 ──────────────────────────────────┐
│   - user == nil → 用户不存在                        │
│   - user.Status == 0 → 账号已禁用                   │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 4. 密码验证（智能模式）───────────────────────────┐
│   utils.CheckPasswordSmart(stored, input)           │
│   - 存储的是 bcrypt 哈希 → bcrypt.Compare           │
│   - 存储的是明文 → 直接比对                         │
│   - 明文匹配成功 → 异步迁移到 bcrypt                │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 5. 签发 JWT Token ────────────────────────────────┐
│   mgr := jwt.NewManager()                           │
│   token, _ := mgr.IssueToken(userID, username)      │
│                                                      │
│   Claims 包含:                                       │
│   - user_id:   用户ID                               │
│   - user_name: 用户名                               │
│   - iat:       签发时间                             │
│   - exp:       过期时间（当前 + JWTExpireTime 分钟） │
│   - iss:       签发者（AppName）                    │
│                                                      │
│   签名算法: HS256                                    │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 6. 写入 Session（Redis）──────────────────────────┐
│   session.Set(MD5(username), {                       │
│     Username, Token, LoginTime                       │
│   })                                                 │
│   → 存入 Redis（7天有效期）                          │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 7. 返回响应 ──────────────────────────────────────┐
│   {                                                  │
│     "code": 0,                                       │
│     "data": {                                        │
│       "user": { "id": 1, "username": "admin" },     │
│       "token": "eyJhbGciOiJIUzI1NiIs..."            │
│     }                                                │
│   }                                                  │
└─────────────────────────────────────────────────────┘
```

### 5.2 AuthJWT 中间件执行流程

**文件**：`middlewares/auth.go`

```
每个 Protected 请求
        │
        ▼
┌─ 1. 检查 skip_jwt 标记 ────────────────────────────┐
│   如果有 skip_jwt=true → 直接放行（Public 路由）     │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 2. 提取 Token ────────────────────────────────────┐
│   从 Authorization: Bearer xxx 获取                  │
│   Fallback: 从 URL Query ?token=xxx 获取            │
│   （用于文件下载等 window.open 场景）                │
│   失败 → 返回 401                                   │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 3. 解析/验签 ─────────────────────────────────────┐
│   jwt.NewManager().ParseToken(tokenStr)              │
│   - 验证签名算法 = HS256                            │
│   - 验证签名完整性（SignKey）                        │
│   - 验证过期时间                                    │
│   失败 → 返回 401（区分过期/无效/格式错误）          │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 4. 查库验证用户存在 ──────────────────────────────┐
│   models.NewUser().GetUserByID(claims.UserID)        │
│   用户不存在 → 返回 401                              │
└─────────────────────────────────────────────────────┘
        │
        ▼
┌─ 5. 写入 Gin Context ─────────────────────────────┐
│   ctx.Set("user_id", int64)          // RBAC 用     │
│   ctx.Set("current_user_id", string) // 兼容旧代码  │
│   ctx.Set("current_user_name", string)              │
│   ctx.Set("current_user", *User)     // 完整用户对象│
└─────────────────────────────────────────────────────┘
        │
        ▼
      ctx.Next()  →  后续 Handler 正常执行
```

## 六、Token 刷新机制

### 6.1 前端自动刷新

**文件**：`k8s-web/src/api/http.js`（响应拦截器）

```
收到 401 响应
    │
    ├── 是 login/register/refresh 接口本身？
    │   └── YES → 清除认证 → 跳转登录页（避免死循环）
    │
    ├── 已有 refresh 在进行中？
    │   └── YES → 加入等待队列（并发锁）
    │
    └── NO → 发起 refresh
              │
              ▼
        POST /auth/refresh
        Headers: Authorization: Bearer <old_token>
              │
              ▼
        成功 → setToken(newToken)
             → 释放队列（所有排队请求用新 token 重试）
             → 重试原始请求
              │
        失败 → clearAuth() → 跳转 /login
```

**并发刷新锁**：多个请求同时 401 时，只有第一个触发 refresh，其余排队等待新 token。

### 6.2 后端 Refresh 逻辑

**文件**：`pkg/jwt/refresh.go`

```go
func (m *Manager) Refresh(tokenString string) (string, error) {
    // 1. 解析旧 Token（允许已过期，但必须签名有效）
    // 2. 检查是否在 MaxRefresh 窗口内（从 iat 起算）
    //    cutoff = now - MaxRefresh - 30s(时钟偏差容忍)
    //    if claims.IssuedAt < cutoff → 拒绝刷新
    // 3. 更新 ExpiresAt 为新的过期时间
    // 4. 用相同 Claims 重新签名，返回新 Token
}
```

**刷新规则**：
- Token 可以已过期，但签名必须正确
- 从**签发时间**（IssuedAt）起算，不超过 MaxRefresh 窗口
- 超过窗口 → 必须重新登录

## 七、退出登录

### 7.1 前端

```javascript
// 清除 localStorage/sessionStorage 中的 token 和 user
clearAuth()
// 跳转登录页
window.location.assign('/login')
```

### 7.2 后端

**文件**：`internal/app/controllers/api/v1/auth/logout.go`

```
POST /api/v1/auth/logout
    │
    ▼
1. 清空 Redis Session 数据（sess.Clear()）
2. 设置 Cookie MaxAge=-1（立即过期）
3. 保存 Session
4. 返回 { "msg": "退出成功" }
```

> **注意**：退出登录**不会使现有 JWT 失效**。JWT 是无状态的，只有等到自然过期才会失效。如需立即吊销，需实现 Token 黑名单机制。

## 八、密码安全策略

### 8.1 存储方式

- **新用户注册**：密码直接存储（建议升级为 bcrypt）
- **旧用户登录**：智能检测密码格式
  - 如果是 bcrypt 哈希（`$2a$`/`$2b$`/`$2y$` 开头）→ 用 bcrypt 验证
  - 如果是明文 → 直接比对，匹配成功后**异步迁移**到 bcrypt

### 8.2 迁移机制

```go
if needMigrate {
    go func() {
        svc.MigrateUserPassword(user.ID, plainPassword)
        // → bcrypt.GenerateFromPassword(password, cost=10)
        // → UPDATE user SET password = bcryptHash WHERE id = ?
    }()
}
```

## 九、前端请求拦截器

**文件**：`k8s-web/src/api/http.js`

### 请求拦截器（每个请求执行）

```javascript
http.interceptors.request.use((config) => {
  // 1. 注入 JWT Token
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }

  // 2. 注入 X-Cluster-ID（仅集群资源接口）
  if (needsClusterID(config.url)) {
    config.headers['X-Cluster-ID'] = clusterStore.current?.id
  }

  // 3. GET 请求添加时间戳防缓存
  if (config.method === 'get') {
    config.params._t = Date.now()
  }
})
```

## 十、JWT Claims 结构

```go
type Claims struct {
    UserID   string `json:"user_id"`    // 用户 ID（字符串）
    UserName string `json:"user_name"`  // 用户名
    jwtpkg.StandardClaims               // 标准字段
}
```

标准字段包含：
| 字段 | 含义 | 示例 |
|------|------|------|
| `iss` | 签发者 | `k8soperation` |
| `iat` | 签发时间 | `1715644800` |
| `nbf` | 生效时间 | `1715644800`（与 iat 相同） |
| `exp` | 过期时间 | `1715652000`（iat + ExpireTime） |

## 十一、Session 存储

### Redis Session Store

**初始化**：`initialize/session.go`

| 配置项 | 值 | 说明 |
|--------|------|------|
| Store | Redis | 分布式 Session 存储 |
| MaxAge | 7天 | Session 有效期 |

## 十二、安全设计总结

| 安全特性 | 实现方式 |
|----------|---------|
| 认证协议 | JWT Bearer Token (HS256) |
| 密码存储 | bcrypt 哈希（自动迁移旧明文） |
| Token 传输 | Authorization Header（不走 Cookie） |
| Token 刷新 | 滑动窗口刷新（MaxRefresh 限制） |
| 并发安全 | 前端刷新锁（防止多请求重复 refresh） |
| Session 存储 | Redis（支持分布式、7天有效期） |
| Cookie 安全 | HttpOnly + Secure + SameSite=Lax |
| 账号状态 | 每次请求查库验证用户存在且可用 |
| 敏感信息 | Token 不含密码，响应不返回密码 |
| 公开接口 | AuthJWTSkip 白名单机制 |
