## 3. 版本规范

### 命名规则

```
v{major}.{minor}.{patch}

示例：v1.1.3, v1.2.0
```

### 规则

| 规则 | 说明 |
|------|------|
| Git Tag = 镜像 Tag | `v1.1.3` 对应 `devops-be:v1.1.3` + `devops-fe:v1.1.3` |
| 前后端同步发版 | 同一个 Tag 包含前后端，镜像版本号一致 |
| 双仓库同步推送 | Gitee (origin) + GitLab (gitlab) 同时推送 |

### 历史版本

```
v1.0.0 → v1.0.1 → v1.1.0 → v1.1.1 → v1.1.3
```

## 5. Docker 镜像构建

> **重要：Apple Silicon (M1/M2/M3) 必须指定 `--platform linux/amd64`**  
> 线上 K8s 集群为 amd64 架构。

### 5.1 后端镜像（多阶段构建，推荐）

```bash
cd /Users/dai/k8s_operation-main

# 构建后端镜像（Docker 内编译，无需本地 Go 环境）
docker build -f docker/backend/Dockerfile \
  --platform linux/amd64 \
  -t registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-be:v版本号 \
  .
```

**后端 Dockerfile 特点：**
- Stage 1：`golang:1.24-alpine` 编译阶段
- Stage 2：`alpine:3.20` 运行阶段（< 25MB）
- 自带健康检查 `/healthz/live`
- 非 root 用户运行（UID 1000）
- 镜像内置 `configs/jenkins-templates/` 和 `configs/dockerfile-templates/`

### 5.2 前端镜像

```bash
cd /Users/dai/k8s_operation-main

# 构建前端镜像（注意 context 是 ./k8s-web）
docker build -f docker/frontend/Dockerfile \
  --platform linux/amd64 \
  -t registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-fe:v版本号 \
  ./k8s-web
```

**前端 Dockerfile 特点：**
- Stage 1：`node:22-alpine` 构建阶段
- Stage 2：`nginx:alpine` 运行阶段
- 内置 Nginx 配置（API 反向代理 + Vue Router History 模式）
- 支持 `API_BACKEND_URL` 环境变量动态注入后端地址
- 自带健康检查 `/health`

### 5.3 验证镜像

```bash
# 查看镜像大小
docker images | grep devops

# 快速测试后端
docker run --rm -p 8080:8080 \
  registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-be:v版本号

# 快速测试前端
docker run --rm -p 80:80 \
  registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-fe:v版本号
```

## 8. K8s 集群部署

### 8.1 部署架构

```
deploy/
├── backend/          # namespace: k8soperation
│   ├── namespace.yaml
│   ├── secret.yaml          # 敏感配置（不入 Git）
│   ├── configmap.yaml       # 平台配置（config.yaml）
│   ├── pv.yaml              # 持久化存储
│   ├── pvc.yaml
│   ├── service.yaml         # ClusterIP + RBAC
│   └── deployment.yaml      # 后端 Deployment
├── frontend/         # namespace: k8soperation
│   ├── deployment.yaml
│   ├── service.yaml
│   └── ingress.yaml         # 可选
├── jenkins/          # namespace: devops
│   ├── namespace.yaml
│   ├── secret.yaml          # Jenkins 凭证
│   ├── configmap.yaml       # JCasC 配置
│   ├── statefulset.yaml
│   └── ...
└── kustomization.yaml
```

### 8.2 首次全量部署

```bash
# 1. 创建后端 Secret（从示例文件复制并填写真实值）
cp deploy/backend/secret.yaml.example deploy/backend/secret.yaml
# 编辑填写数据库、Redis、Jenkins 等真实配置
vim deploy/backend/secret.yaml

# 2. 部署后端（自动创建 namespace + 全部资源）
kubectl apply -k deploy/backend/

# 3. 部署前端
kubectl apply -k deploy/frontend/

# 4. 部署 Jenkins（独立 namespace: devops）
kubectl apply -k deploy/jenkins/
```

### 8.3 版本更新（日常发布）

```bash
# === 更新后端镜像版本 ===
kubectl -n k8soperation set image deployment/k8soperation \
  k8soperation=registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-be:v版本号

# === 更新前端镜像版本 ===
kubectl -n k8soperation set image deployment/k8soperation-web \
  devops-fe=registry.cn-hangzhou.aliyuncs.com/k8s-gos/devops-fe:v版本号

# === 或修改 YAML 后 apply ===
# 编辑 deploy/backend/deployment.yaml 中的 image 字段
# 编辑 deploy/frontend/deployment.yaml 中的 image 字段
kubectl apply -k deploy/backend/
kubectl apply -k deploy/frontend/
```

### 8.4 监控滚动更新

```bash
# 查看后端更新状态
kubectl -n k8soperation rollout status deployment/k8soperation

# 查看前端更新状态
kubectl -n k8soperation rollout status deployment/k8soperation-web

# 查看 Pod 状态
kubectl -n k8soperation get pods -w
```

### 8.5 更新 ConfigMap（配置变更时）

```bash
# 如果修改了 configmap.yaml 中的配置
kubectl apply -f deploy/backend/configmap.yaml

# 重启后端使配置生效
kubectl -n k8soperation rollout restart deployment/k8soperation
```

### 8.6 更新 Jenkins 凭证/配置

```bash
# 更新 Jenkins Secret（凭证更新，如 Gitee Token）
kubectl apply -f deploy/jenkins/secret.yaml

# 更新 JCasC 配置
kubectl apply -f deploy/jenkins/configmap.yaml

# 重启 Jenkins 使 JCasC 重新加载
kubectl -n devops rollout restart statefulset jenkins
```

> **注意：** Jenkins 使用 JCasC，每次重启会从 ConfigMap + Secret 重新加载所有凭证配置。  
> 在 Jenkins UI 手动修改的凭证会在重启后被覆盖。**必须修改 K8s Secret 才是持久化变更。**

## 9. Jenkins 部署与更新

### 9.1 Jenkins 凭证管理

凭证由 `deploy/jenkins/secret.yaml` 管理，通过 JCasC 自动注入：

| 凭证 ID | 类型 | 用途 |
|---------|------|------|
| `gitee-id` | usernamePassword | Git 代码拉取 |
| `harbor-registry` | usernamePassword | 阿里云 ACR 镜像推送 |
| `hmac-secret` | string | 平台回调 HMAC 签名 |
| `sonarqube-token` | string | 代码质量扫描 |

**更新 Git 凭证示例（如更换 Gitee Token）：**

```bash
# 1. 生成 base64 编码
echo -n "oauth2" | base64          # → b2F1dGgy
echo -n "新的Token" | base64       # → xxxxx

# 2. 更新 secret.yaml 中的 gitee-username 和 gitee-password

# 3. 应用到集群
kubectl apply -f deploy/jenkins/secret.yaml

# 4. 重启 Jenkins
kubectl -n devops rollout restart statefulset jenkins
```

### 9.2 Jenkins 构建模板更新

Groovy 模板跟随后端镜像打包（`configs/jenkins-templates/` 目录）。

更新方式：
1. 修改 `configs/jenkins-templates/*.groovy`
2. 重新构建后端镜像（模板被 COPY 进镜像）
3. 推送新镜像并更新 K8s Deployment

或使用 ConfigMap 覆盖（可选）：
```bash
kubectl -n k8soperation create configmap k8soperation-jenkins-templates \
  --from-file=configs/jenkins-templates/ --dry-run=client -o yaml | kubectl apply -f -
kubectl -n k8soperation rollout restart deployment/k8soperation
```

## 11. 常见问题排查

### 11.1 镜像拉取失败

```bash
# 检查 imagePullSecrets
kubectl -n k8soperation get secret aliyun-registry

# 如果不存在，创建
kubectl -n k8soperation create secret docker-registry aliyun-registry \
  --docker-server=registry.cn-hangzhou.aliyuncs.com \
  --docker-username=15862326490 \
  --docker-password=<ACR密码>
```

### 11.2 Apple Silicon 构建架构问题

```
# 症状：exec format error
# 原因：M1/M2 默认构建 arm64 镜像，K8s 集群是 amd64

# 解决：构建时指定平台
docker build --platform linux/amd64 ...
```

### 11.3 Jenkins 凭证重启后丢失

```
原因：JCasC 每次启动从 K8s Secret 重新加载凭证，覆盖 UI 手动修改

解决：修改 deploy/jenkins/secret.yaml → apply → restart
```

### 11.4 后端启动失败

```bash
# 查看日志
kubectl -n k8soperation logs deploy/k8soperation

# 常见原因：
# - DB 连接失败 → 检查 Secret 中的 DB_HOST/DB_PORT
# - Redis 连接失败 → 检查 REDIS_ADDRESS
# - 配置解析错误 → 检查 configmap.yaml 的 YAML 格式
```

### 11.5 前端白屏

```bash
# 检查 Nginx 配置和后端代理
kubectl -n k8soperation exec deploy/k8soperation-web -- cat /etc/nginx/conf.d/default.conf

# 检查后端是否可达
kubectl -n k8soperation exec deploy/k8soperation-web -- \
  wget -qO- http://k8soperation.k8soperation.svc:8080/healthz/live
```

## 附录 A：一键发布脚本（完整流程）

```bash
#!/bin/bash
# ============================================
# K8sOperation 一键发布脚本
# 用法：./release.sh v1.2.0 "版本说明"
# ============================================
set -e

VERSION=${1:?"用法: $0 <版本号> <说明>"}
MESSAGE=${2:-"Release $VERSION"}
REGISTRY="registry.cn-hangzhou.aliyuncs.com/k8s-gos"

echo "========== 发布版本: $VERSION =========="

# 1. 编译验证
echo "[1/7] 编译验证..."
go build ./...
cd k8s-web && npm run build && cd ..

# 2. 构建镜像
echo "[2/7] 构建 Docker 镜像..."
docker build -f docker/backend/Dockerfile --platform linux/amd64 \
  -t $REGISTRY/devops-be:$VERSION .
docker build -f docker/frontend/Dockerfile --platform linux/amd64 \
  -t $REGISTRY/devops-fe:$VERSION ./k8s-web

# 3. 推送镜像
echo "[3/7] 推送镜像到 ACR..."
docker push $REGISTRY/devops-be:$VERSION
docker push $REGISTRY/devops-fe:$VERSION

# 4. Git 提交
echo "[4/7] Git 提交..."
git add -A
git commit -m "feat($VERSION): $MESSAGE" || echo "无新变更"

# 5. 创建 Tag
echo "[5/7] 创建 Tag: $VERSION..."
git tag -a $VERSION -m "$VERSION: $MESSAGE"

# 6. 双仓库推送
echo "[6/7] 推送到 Gitee + GitLab..."
git push origin main --tags
git push gitlab main --tags

# 7. 更新 K8s
echo "[7/7] 更新 K8s Deployment..."
kubectl -n k8soperation set image deployment/k8soperation \
  k8soperation=$REGISTRY/devops-be:$VERSION
kubectl -n k8soperation set image deployment/k8soperation-web \
  devops-fe=$REGISTRY/devops-fe:$VERSION

echo "========== 发布完成: $VERSION =========="
kubectl -n k8soperation rollout status deployment/k8soperation
kubectl -n k8soperation rollout status deployment/k8soperation-web
```
